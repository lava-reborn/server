# LAVA Online — восстановление сервера

Клиент: `~/Desktop/LAVA` (2.1 ГБ, 29 840 файлов). Игра VR-Ocean, серверы мертвы,
домены `lava-online.ru` не резолвятся.

## Что уже сделано

- Клиент разобран: `res/main.swf` — **ActionScript 2** (SWF v9, ни одного тега DoABC).
- Декомпилирован JPEXS FFDec → **395 классов** с оригинальными именами пакетов `lol.*`
  в `recon/as-src/`. Это фактически исходный код клиента.
- Протокол полностью восстановлен и описан в [PROTOCOL.md](PROTOCOL.md).
- Прототип сервера `server/` проходит рукопожатие: 29 тестов кодека + e2e-тест.

## Запуск

```bash
cd server && python3 test_protocol.py && python3 test_handshake.py
```

Сервер: `LAVA_PORT=9775 python3 server/server.py`

## Ключевые факты

**Протокол тривиален.** Flash XMLSocket, кадры — plain text в CP1251,
завершённые `\0`, формат `команда;ключ=значение;`. Никакого шифрования,
никакого бинарного пакинга, никаких контрольных сумм. Тип значения задан
первым символом (`@` строка, `H` hex, `|` список, `x` big-uint, цифра — число).

**Словарь известен целиком.** 53 команды клиент→сервер (таблица с параметрами:
`recon/notes/cs_commands.txt`) и 239 подписок сервер→клиент
(`recon/notes/sc_commands.txt`).

**Авторизация — не препятствие.** Клиент берёт хеш по HTTP с сайта
(`game_session.php?session=`) и шлёт `login;hash=@...@;`. Сервер отвечает
`cmdAck;res=0;`. Свой сервер принимает любой хеш.

## Чего НЕТ и что придётся писать заново

Это главное. Протокол — это форма, а не содержание.

| Есть на клиенте | Нет нигде |
|---|---|
| `type_id` → имя для 29 486 предметов | урон, вес, цена, требования |
| `type_id` → имя для 5 990 мобов | HP, агрессия, лут, опыт |
| геометрия 1 399 локаций | спавны, маршруты, респаун |
| тексты 417 точек глобальной карты | квестовые цепочки и условия |

Весь числовой баланс, ИИ мобов, боевая математика, экономика, генерация лута
жили на сервере. Их надо не реверсить, а **проектировать с нуля** — и это 90%
работы. Реверс протокола, самая «страшная» на вид часть, уже закрыт.

## Блокер: Flash мёртв

Flash ActiveX на машине не установлен, и Adobe его больше не раздаёт.
`ClientLoader.dll` (.NET, есть .NET 4.8) хостит `AxShockwaveFlash` — без плагина
он не запустится. Варианты:

1. **Ruffle** — открытый эмулятор Flash. AS2 поддерживает хорошо. Клиент
   тогда живёт в браузере, сокет придётся проксировать через WebSocket.
2. **Flash Player projector** из архивов — аутентично, но это запуск
   необновляемого EOL-бинаря.
3. Переписать клиент. Долго, но графика и геометрия локаций уже извлечены.

Ruffle — рекомендуемый путь: без него нельзя даже увидеть результат работы сервера.

## План

**Этап 1. Довести до входа в игру.** Реализовать `selPers`/`newPers`/`actPlayer`
и ответы `persInfo`, `accountInfo`, `lenter`. Цель — персонаж стоит в локации.
Здесь же поднять Ruffle и WebSocket-мост, иначе проверять нечем.

**Этап 2. Мир.** `moveTo` + рассылка `userMove`/`addPlayer`/`removePlayer`
окружающим, чат (`userMsg` → `chatRes`). Это уже играбельная песочница с
несколькими игроками.

**Этап 3. Контент.** Мобы, бой (`fire`/`faHit`/`caHit`), предметы (`ss_*`),
квесты (`q_*`). Баланс проектируется заново, сверяясь со скриншотами и
воспоминаниями игроков.

**Этап 4. Социальное.** Кланы, почта, аукцион, поля боя.

Этапы 1–2 — реально недели. Этапы 3–4 — это и есть «написать MMO»,
там счёт на месяцы, как было у MaNGOS и L2J.

## Правовая рамка

Реверс мёртвой игры ради совместимости и сохранения — обычная практика
(MaNGOS, rAthena, L2J, OpenSpades). Здесь пишется **только серверная часть**,
клиент не модифицируется и не распространяется: игроки приносят свою копию.
Ассеты VR-Ocean остаются у правообладателя — не выкладывать `res/` в репозиторий.
