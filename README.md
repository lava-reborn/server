# LAVA Online — восстановление сервера

Серверная часть для мёртвой российской MMO **LAVA Online** (VR-Ocean, 2008–2018).
Клиент — Flash/ActionScript 2, официальные серверы выключены, домены не
резолвятся. Здесь пишется **только сервер**; клиент не модифицируется и не
распространяется, игрок приносит свою копию.

Состояние на 18 сентября 2026: настоящий клиент под Flash Player projector
регистрируется, входит и играет. Несколько игроков видят друг друга, ходят,
переписываются в каналах и приватом, собираются в отряд и шлют письма с
деньгами и вложениями. У персонажа настоящие характеристики: атрибуты,
навыки, специализации с обучением у учителя, опыт, деньги. Инвентарь:
покупка и продажа у торговцев, слоты, зарядка оружия — всё с сохранением.
Бой: выстрел и удар по кадрам оригинала, очки действия, мобы с ИИ, лут и
смерть — с потерей вещи из рюкзака, тремя видами возрождения и переносом на
место прописки; мёртвым можно и войти в игру. Тринадцать квестов, лекарь,
прописка. Глобальная карта
на 262 восстановленные клетки, из локации можно выйти не только на карту,
но и в соседнюю клетку по стороне выхода. Сервер останавливается мягко,
сохраняя всех, кто в игре, и поднимается в docker — друзьям отдаётся адрес и
один `LavaReborn.exe`, ресурсы игры каждый приносит свои.

Полный разбор клиента по подсистемам и план «нормального» сервера — в
[TASKS.md](TASKS.md) и `recon/analysis/`.

## Запуск

Нужны: Windows с WSL (серверы крутятся там, Python только WSL-овский), клиент
в `~/Desktop/LAVA`, Flash Player projector 32.0.0.465 в `tools/flash/`
(качается с `fpdownload.macromedia.com/pub/flashplayer/updaters/32/flashplayer_32_sa.exe`).

```bash
./run.sh            # серверы + клиент
./run.sh servers    # только серверы
./run.sh stop
./run.sh log        # хвост logs/game.log
```

Регистрация — в браузере на `http://127.0.0.1:8080/`. Тестовый аккаунт
`polestvr` / `lava1234`.

Тесты (двадцать серверных наборов и шесть по данным, все обязаны быть
зелёными перед коммитом):

```bash
cd server && for t in test_protocol test_accounts test_handshake test_locations test_world test_bootstrap test_shutdown test_progression test_inventory test_two_clients test_pvp test_quests test_social test_items test_combat test_travel test_terrain_move test_death test_transport test_admin; do python3 $t.py || break; done
cd .. && for t in test_wiki_data test_world_data test_settlements test_terrain test_borders test_transport_data; do python3 data/$t.py || break; done
python3 tools/test_export_texts.py
```

Переменные: `LAVA_GX`/`LAVA_GY` — стартовая клетка карты (6268×1819, Нубийское поселение),
`LAVA_LOC` — принудительный id локации, `LAVA_DEBUG=1` — отладочный projector
с `flashlog.txt`, `LAVA_PLAYER=ruffle` — Ruffle (рисует интерфейс в 313×107,
непригоден).

Команды чата, наши, не игры: `/where` — где стою (название, файл, клетка) и
`/home` — домой (куда прописан у жителя, иначе на старт; тем же путём пойдёт
возрождение). Обе ничего не создают, поэтому открыты всем.

`/goto`, `/give` и `/money` отсюда убраны: они делали деньги, предметы и
расстояние из воздуха для любого, кто их наберёт. Это дело
[панели администратора](#панель-администратора). Для разработки они остались
под `LAVA_CHEATS=1`, который не ставит ни один запускающий скрипт.

Аренда транспорта: у арендодателя (в Вади-Хальфе это Шихаб на чёрном рынке)
окно «Аренда» показывает, что он сдаёт, срок 1..365 дней и цену за день.
Ослик — 0.1 голды в день и +70 % к скорости на карте, дальше по возрастанию
до Ларвы (+350 %). Пока аренда идёт, `userInfo_Player` несёт `tr`/`tr_hours`,
и перелёты по карте идут быстрее ровно во столько раз. Таблица —
`data/transport.json`, провод — `server/transport.py`.

### Что происходит, когда убивают

HP до нуля — и фигура падает там, где стояла: соседи видят труп, автоогонь
и мобы сбрасывают его с цели, а сам игрок получает окно возрождения. Пока
оно открыто, сервер не принимает от него ничего, кроме возрождения (ходить,
стрелять, уйти на карту и даже поговорить в чат нельзя), но на запросы вроде
«покажи рюкзак» по-прежнему отвечает — иначе у клиента навсегда закроется
очередь этих запросов. Из рюкзака на месте гибели остаётся один незакреплённый
предмет из тех, что вики помечает «выпадает при смерти»: обычный мешок, любой
может подобрать.

Смерть переживает выход из игры: вошедший мёртвым так и войдёт мёртвым, и
клиент сам поднимет ему то же окно (`persInfo;death=1`).

В окне три кнопки, и они разные:

| Кнопка | Цена | Итог |
|---|---|---|
| Бесплатно | подождать 15 с (окно само нажмёт её, когда отсчёт кончится) | четверть HP, ноль выносливости |
| 5 голды | 5 голды | HP и выносливость целиком, сразу |
| 500 афро | 500 афро (те же 5 голды по курсу сервера) | HP и выносливость целиком, сразу |

Возрождение **всегда** переносит на место прописки (`on_conv;op=0` у жителя
с `can_set_home`), а без прописки — в стартовую локацию. На месте гибели не
оставляет никогда. Проверить дорогу, не умирая, можно командой `/home` — из
боя она, как и выход на карту, откажет.

### Бой между игроками и перехват на карте

Стрелять друг в друга можно там, где это разрешили сами разработчики:
`pvp="1"` в XML локации, 828 файлов из 1353. Атрибута нет у пустошных
тайлов, и это не упущение — открытая пустошь мирная, драка идёт в
объявленных местах. Сервер не добавляет от себя ни одной локации: удар по
игроку там, где `pvp="0"`, отказывается кодом 3, как и любой выстрел там,
где `war="0"`.

**Выход из локации держит не выстрел, а тот, кто тебя бьёт.** Раньше любой
замах запирал игрока на `leave_combat_timeout`, даже если он промахнулся по
пустому месту и вокруг никого. Теперь `Fighter.in_combat` спрашивает другое:
есть ли моб, взявший тебя целью, и был ли обмен ударами с человеком за
последние 30 с. Убил моба с одного выстрела или разбудил только эхо — уходи
сразу. Дуэль держит **обе** стороны, и открывшего её тоже: иначе всякая
стычка кончалась бы в ту секунду, когда пошла не так.

**Перехват** — это меню на глобальной карте по Shift с кликом по игроку
(`DisplayGlobalMap.playerMcOnPress`), пункт «перехват». Клиент шлёт
`moveTo;trg=<id>` и больше ничего: где цель — дело сервера, а она идёт.
Поэтому это погоня, а не доставка: `Session.pursue` раз в секунду
перенацеливается на текущее положение беглеца, пока не подойдёт на треть
клетки. Дальше обоих затягивает в локацию, которая стоит на этой клетке, —
догнать и встать рядом на карте было бы не перехватом, а конвоем: беглец
просто пошёл бы дальше. Согнанного не спрашивают, поэтому рамки узкие:
только на своей клетке, только с тем, кто на карте, а стрелять там или нет
решает сама локация — большая часть пустоши между людьми мирная, и перехват
этого не отменяет.

### Кто чем торгует — редактором, а не правкой вики

Имена жителей и их ассортимент приходят из двух таблиц, которые делались не
для этого мира: `mobs.xml` зовёт НПС по тому, кто был приписан рядом в
2008-м, а списки товаров сняты с вики, то есть с сервера, который давно
выключен. И то и другое — хорошая отправная точка и ни разу не решение.

Решения живут в `data/npcs.json`, его пишет
[`tools/npc_editor.py`](tools/npc_editor.py):

```bash
python3 tools/npc_editor.py     # страница на 127.0.0.1:8091
```

Выбираешь локацию — он показывает, кто в ней стоит, прямо из XML клиента
(1345 локаций с жителями, в Вади-Хальфе их 21). У каждого поле имени, а у
торговца ещё список товаров: поиск по каталогу, клик добавляет, крестик
убирает. «Сохранить» дописывает файл, не затирая решения по другим локациям.

Ключ — **тип существа**, а не локация: так думают и клиент, и сервер
(`items.stock_for` берёт тип торговца, имя едет самим type_id), и два рынка
с одним типом торговца ставят одного и того же торговца.

Читает это `server/npcs.py` при старте: `names.py` берёт оттуда имя поверх
вики и поверх правила о хранилищах, `items.stock_for` — список товаров.
Пустой список там — тоже решение («не торгует»), а не отсутствие записи.
Сервер после правки нужно перезапустить, а если менялись имена — ещё и
пересобрать лаунчер (таблица строк едет внутри exe).

Расстановку этот редактор не трогает: подвинуть жителя — задача того же
рода, что рисование карты, и обоим место в одном инструменте позже.

### Хранилища вместо имён

Часть «жителей» — не люди: их спрайт это сейф (`1f_Safe`, `1f_BankSafe`,
`1f_Seif_Stary`, 22 типа), и они открывают окно хранения, а не разговор.
`mobs.xml` всё равно зовёт их по писарю, а вики ещё и записала его имя:
сейф на чёрном рынке Вади-Хальфы (2424) приходил игроку как **«Аарон»**.
`names.py` переименовывает всё, что нарисовано сейфом, в «Хранилище», и
делает это по папке графики, а не по списку id, — новая локация с ящиком
получит правильное имя сама.

Таблица строк едет игроку **внутри exe**, так что переименование доходит
до людей только с новой сборкой лаунчера: `launcher/build.ps1`, затем
заливка в `download/` сайта.

### Стартовая зона заперта намеренно

Нубийская долина обнесена стеной: внутри 112 клеток и 16 посёлков, снаружи
остальные 246. Это решение владельца, а не рельеф — карта долину не окружает.
Остальные города пока сыры, и выход к ним задуман квестом; до тех пор новичок
играет в долине.

Стена нарисована руками в [`tools/map_editor.py`](tools/map_editor.py): он
поднимает страницу на `127.0.0.1:8090`, кладёт на неё тайлы карты самого
клиента и даёт кисть — красным непроходимое, зелёным обязательно проходимое.
Пишет в `data/terrain_verified.json`; «Проверить» обходит мир так, как его
оставит рисунок, и называет отрезанные посёлки **до** сохранения.

Почему руками, а не порогом: распознавание упирается в потолок. Шероховатость
находит гребни и оставляет тело массива открытым, отчего сквозь нарисованную
гору проходишь; яркость хватает вади и тени дюн и при 160 отрезает 247
посёлков из 262. Разница между хребтом и валунным полем не в пикселях.

Старшинство в `world.passable()`: **рука** (`terrain_verified.json`) →
**объявленный выход** (`terrain_repairs.json`) → **фотография**
(`map_terrain.json`). Каждый следующий слабее предыдущего.

Выход из локации «в другую локацию» (`chWorld;to=1`) работает по стороне
клетки выхода: стороны W/N/E/S ведут в соседнюю клетку карты с прибытием на
противоположный край, двери a/b — в интерьер из `data/exits.json`, если цель
известна хотя бы со средней уверенностью, иначе отказ строкой в чат. По краю
мира (5833..6335 × 1600..2143) стоит кольцо скал: у этих файлов нет выхода
наружу, поэтому за карту не выйти, а сам край — это место, куда доходишь.
Где путь всё-таки кончается (озеро), открывается «карман» — тупиковая
скальная сцена с единственным выходом назад. Всё это — `server/travel.py`.

## Раздача: docker и пакет игрока

Всё выше — разработка на одной машине, через `run.sh`. Чтобы позвать друзей,
поднимается то же самое в docker, а игроку отдаётся один `LavaReborn.exe`.
**Ресурсы игры не раздаются**: клиент у игрока свой, и ни один файл из `res/`
не уходит ни в образ, ни на HTTP, ни в этот exe.

Работает это потому, что клиент, запущенный с диска, в сеть почти не ходит.
Он пробует загрузить `xmldocs/csettings_v1.xml`, не находит его (в выпущенном
клиенте этого файла нет) и переходит в режим LOCAL: графика, звук, локации,
аватары — всё с диска, адрес сервера — из флешваров `var_host`/`var_port`, а
по сети остаётся один игровой сокет. Полный разбор со ссылками на строки
исходников — [`recon/analysis/local-mode.md`](recon/analysis/local-mode.md).

### Подъём

```bash
cp .env.example .env         # и поправить LAVA_RES_DIR и LAVA_PUBLIC_HOST
docker compose up -d --build
docker compose logs -f game
docker compose down          # SIGTERM доходит до сервера, всех сохраняет
```

Два сервиса из одного образа: `game` — игровой сокет, `http` — страница
регистрации. Разделены потому, что останавливать надо именно сервер, а
`docker stop` шлёт сигнал одному процессу.

| переменная | по умолчанию | что делает |
|---|---|---|
| `LAVA_RES_DIR` | — (обязательна) | папка `res/` игрока, монтируется read-only; сервер читает из неё локации, `database/mobs.xml` и `objects.xml` |
| `LAVA_PUBLIC_HOST` | `127.0.0.1` | адрес, который страница регистрации показывает игрокам |
| `LAVA_GAME_PORT` | `9775` | опубликованный порт игрового сокета |
| `LAVA_HTTP_PORT` | `8080` | опубликованный порт страницы регистрации |
| `LAVA_BIND` | `0.0.0.0` | на каком интерфейсе публиковать; `127.0.0.1` — только через туннель |
| `LAVA_LOG_LEVEL` | `INFO` | `DEBUG` — провод в лог |
| `LAVA_HTTP_RES` | `0` | раздавать ли `/res/**` по HTTP. **Ноль — это и есть смысл затеи**: раздача включает и `csettings_v1.xml`, а он переводит клиент в режим WEB, то есть на загрузку всего с сервера |
| `LAVA_ADMINS` | — | игровые логины через запятую, которым открыта панель `/admin`. Пусто — панели нет вовсе, все её адреса отвечают 404 |
| `LAVA_ADMIN_HOURS` | `12` | сколько держится вход в панель |
| `LAVA_POLICY_PORT` | `8430` | порт политики Flash внутри контейнера; наружу docker публикует на него 843 (`LAVA_POLICY_PUBLIC_PORT`), поэтому привилегированный bind достаётся докеру, а не серверу. Flash спрашивает политику сначала на 843 и только потом переспрашивает в игровом сокете — а если провайдер 843 глушит молча (а не отвечает отказом), эта пауза видна игроку при каждом входе. `0` выключает второй слушатель |

База — именованный том `lava-db`, не bind-mount: на диске Windows,
примонтированном в WSL, sqlite не может взять блокировки WAL и молча
откатывается к журналу, где два процесса начинают мешать друг другу
(TASKS 1.2). Healthcheck: у `game` — рукопожатие политики в игровом сокете, у
`http` — `GET /status`.

Страница регистрации ни при выключенной раздаче, ни при включённой ничего из
`res/` не берёт — она целиком в `bootstrap_http.PAGE`; это проверяется в
`test_bootstrap.py`.

### Панель администратора

`/admin`, вход теми же логином и паролем, что и в игре. Кому открыто —
`LAVA_ADMINS`, список логинов через запятую; пусто — панели нет вовсе, все её
адреса отвечают 404, как любой чужой адрес, чтобы сервер, который под неё не
настраивали, не сообщал о её существовании.

Своего склада паролей у панели нет и не нужно: клиент считает
`md5(cp1251(пароль + логин))` и шлёт только его, этот же хеш лежит в
`accounts` — панель проверяет пароль ровно так же. Логин администратора он же
и есть то имя, которое увидит выкинутый игрок.

Наверху — **кто сейчас в игре**: ник, учётка, где стоит, сколько минут в
игре. Список пишет игровой сервер (таблица `online`), потому что сессии живут
в его процессе, а панель их не видит. Рядом лежит `heartbeat`: без него пустой
список означал бы сразу две разные вещи — «никого нет» и «сервер не пишет», —
и панель говорит об этом прямо, а не показывает пустоту как правду.

Дальше — **поиск по нику или логину**, и уже в найденном: деньги, предмет,
транспорт (все шестнадцать машин, включая те девять, которых нет ни у одного
арендодателя), перенос по номеру локации или координатам, выкинуть, забанить,
разбанить — с причиной, которую игрок увидит. Списком всех подряд панель не
рисует: для трёх учёток это удобно, для трёхсот бесполезно.

Выкидывание идёт механизмом самой игры. `Session.kickban` (`Session.as:199`)
рисует окно «Администратор <имя> ведёт работу над вашим аккаунтом», добавляет
срок недоступности, если он задан, и причину под ним; сервер шлёт кадр и
закрывает сокет, сохранив персонажа по дороге.

**Почему через очередь, а не прямой записью в базу.** Панель живёт в
HTTP-процессе, игра — в другом, общая у них только база. Персонажа, который
сейчас в игре, держит в памяти его сессия, и `Character.save()` при выходе
пишет свои числа поверх. Панель, писавшая бы в таблицу напрямую, теряла бы
каждое изменение онлайн-игрока в момент его выхода. Поэтому панель кладёт
намерение в `admin_actions`, а выполняет игровой сервер, который этими
объектами и владеет: он разбирает очередь раз в секунду
(`LAVA_ADMIN_POLL`), онлайн-игроку изменения приходят сразу, офлайн —
записываются в базу. Проверяется это в `server/test_admin.py`, и проверка там
не «строка изменилась», а «строка осталась изменённой после выхода игрока».

Команды `/goto`, `/give` и `/money` из чата убраны — они делали деньги и
предметы из воздуха для любого, кто их наберёт. В коде они остались под
`LAVA_CHEATS`, выключенным везде, кроме тестовых прогонов: девять наборов
используют их, чтобы ставить сцену, и гонять это через очередь значило бы
проверять очередь вместо того, ради чего набор написан. Ни `run.sh`, ни
compose, ни выкладка этот выключатель не ставят.

### Пакет игрока: один файл

```powershell
powershell -ExecutionPolicy Bypass -File launcher\build.ps1 -ServerHost lava-reborn.ru
```

Кладёт в `dist/` **`LavaReborn.exe`** (17 МБ) и короткий `README.txt`. Игрок
кладёт exe рядом со своей папкой `res` и запускает — больше ничего.

Это не запускалка, а клиент: своё окно входа в дизайн-системе сайта
(`lava-site/design/tokens.json`, тема «Пустошь»), логин и пароль спрашиваются
в нём, и **игра открывается сразу в мире** — ни экрана входа клиента, ни
выбора персонажа игрок не видит.

Внутри exe только то, что игрой не является: Flash Player projector, наша
таблица строк и картинка окна. Сам клиент туда не попадает, не изменяется и
не раздаётся; папку `res` программа только читает и ничего в неё не пишет.

#### Как получается вход сразу в мир

У клиента для этого есть собственная дорога, и она одна
(`lol/core/Session.as:88`):

```actionscript
if (_root.logged == 1 && SSEmulator.PATHTYPE == WEB) {
   LoadVars.sendAndLoad("/exe/lavaclient/loaduser/?ajax", …)   // -> "host:port hash"
   → SceneShifter.enterScene(); connect(host, port, hash)
}
```

То есть нужны три вещи разом: флешвар `logged=1`, режим `WEB` и ответ на
`loaduser`. Режим `WEB` включается тем, что загрузился
`xmldocs/csettings_v1.xml`, а `loaduser` — **корневой** путь, и у фильма,
открытого с диска, его не к чему привязать. Поэтому exe поднимает на
`127.0.0.1` (порт выбирает система) веб-сервер поверх собственной папки `res`
игрока и открывает клиент по `http://127.0.0.1:<порт>/res/main.swf?logged=1`.
Наружу не уходит ни байта: это файлы игрока, отданные его же Flash по петле.
Маршруты те же, что `server/bootstrap_http.py` отдаёт владельцу по `./run.sh`,
и та же подстановка — путь `WEB` это путь `LOCAL` с `base` впереди
(`SSEmulator.getStringURL` и соседи), так что `/res/<x>` это `<res>/<x>`.

Дальше клиент делает остальное сам: после `cmdAck res=0` при
`can_create = 0` `PersGenerator.checkFullInfo` вызывает `selectDefaultPers()`
и шлёт `selPers` без всякого экрана. Экран создания персонажа остаётся там,
где ему и место, — у новой учётной записи.

Пароль проверяется **до** запуска игры, на игровом же сокете: `hello` →
`login` → `cmdAck`. Поэтому «неверный логин или пароль» пишется в нормальном
окне, а не строчкой статуса внутри Flash, и сервер для этого не понадобилось
трогать — второй сессии на аккаунт он не возражает, а сессия, не выбравшая
персонажа, мира не касается.

Пароль на сервер не уходит: считается `md5(cp1251(пароль + логин))` и
посылается только он (`server/accounts.py:231` — другая половина того же).
«Запомнить меня» хранит этот же хеш под DPAPI текущего пользователя
в `%LOCALAPPDATA%\LavaOnline`; в поле пароля тогда стоит «Пароль сохранён»,
как это делал и оригинальный экран входа.

Пока строится мир, окно остаётся поверх игры и уходит, как только клиент
запросил первую локацию (или через 25 с, если что-то пошло не так — тогда
игрок видит сообщение самого клиента). Файлы, которых не хватило, пишутся в
`%LOCALAPPDATA%\LavaOnline\missing.log`: 404 на ресурс — это чёрный экран без
единой ошибки в клиенте.

Заголовок окна проигрыватель ставит свой и поменять его не даёт, поэтому
запускалка переименовывает окно снаружи, когда оно появится, — и ещё
несколько раз подряд, потому что Flash переписывает заголовок в процессе
запуска.

Запасной режим — `LAVA_LOCAL=1`: клиент открывается по-старому, с диска, со
своим окном входа и файлом доверия `FlashPlayerTrust`. Нужен, если на чьей-то
машине путь через `127.0.0.1` не сложится; в `README.txt` игрока про него
сказано.

Собирается `csc.exe` из состава Windows (.NET Framework), устанавливать
ничего не нужно. Исходники — в [`launcher/`](launcher/): `LoginForm.cs` и
`Theme.cs` — окно и дизайн-система, `LocalServer.cs` — тот самый веб-сервер
по петле, `GameProbe.cs` — рукопожатие, `Creds.cs` — хеш и «запомнить меня».

### Запасной путь: три файла

На случай, когда неподписанный exe не запускают (антивирус, политика
организации):

```bash
LAVA_RES=/путь/к/res python3 tools/make_client_package.py \
    --host lava.example.org --port 9775 --http-port 8080
```

Кладёт в `dist/manual/` три файла и ничего больше:

* `texts.xml` — таблица строк, которую игрок копирует к себе в
  `res/database/`. Это один из двух файлов, которых в выпущенном клиенте нет
  (второй — `hints/hints.xml`, без него просто не будет подсказок). Инвариант
  PROTOCOL §9 в режиме LOCAL никуда не девается: в файле должны быть **все**
  id, которые сервер может прислать, иначе догрузка одной строки после входа
  вернёт игрока на экран логина. `tools/export_texts.py` это проверяет, а
  `tools/test_export_texts.py` — что файл совпадает байт в байт с тем, что
  `bootstrap_http` отдаёт на `?all=1`.
* `lava.bat` — запускалка с подставленным адресом. Флешвары едут в строке
  запроса к `main.swf`: своего ключа командной строки у projector нет.
  Копирует `texts.xml` на место при первом запуске.
* `README.txt` — по-русски: куда что положить, где взять projector, как
  войти.

**Что игрок приносит сам:** свою копию `res/` и Flash Player projector 32
(`fpdownload.macromedia.com/pub/flashplayer/updaters/32/flashplayer_32_sa.exe`).
Дальше — регистрация на `http://<адрес>:8080/` и `lava.bat`.

Если флешвары почему-то не доехали, это не тупик: поля адреса и порта есть в
самом окне входа, и клиент соединяется именно с тем, что в них написано
(`EnterGameInterface.as:162-163`, `:234-235`). В `README.txt` пакета про это
сказано.

## База: файл или общая

Сервер работает с двумя базами, и выбирает окружение:

* `LAVA_DB` — файл SQLite. Так было всегда, так остаётся по умолчанию и
  так гоняются тесты.
* `LAVA_DB_URL` — общий Postgres стойки (`lava-pg`). Задан — файл не
  открывается вовсе, и в той же базе живут сайт и админская панель.

Между кодом и базой стоит `server/storage.py`; `accounts.py` пишет один
и тот же SQL с вопросительными знаками и не знает, куда он поедет.
Разведены по диалектам только те места, где они правда расходятся:
новый идентификатор (`lastrowid` против `INSERT ... RETURNING`, причём
колонка ключа у таблиц разная — `id`, `uniq`, `q_id`), `INSERT OR
REPLACE` против `ON CONFLICT DO UPDATE`, состав таблицы, и `LOWER`,
который в SQLite не знает кириллицы.

Схема одна на обе базы — `SCHEMA` в `accounts.py`. Для Postgres она не
переписывается второй раз, а переводится: DDL прогоняется через SQLite в
памяти, и уже оттуда собираются `CREATE TABLE`. Второй экземпляр схемы
разошёлся бы с первым в первый же вечер.

Проверка поверх Postgres — `server/test_storage_pg.py`; без
`LAVA_DB_URL` набор пропускается.

### Переезд на общую базу

Данные переносит `lava-pg/migrate/sqlite_to_pg.py` (см. README того
проекта). Порядок на боевом сервере:

1. остановить игру — `cd /opt/lava && docker compose stop`;
2. снять копию файла рядом с ним;
3. перенести данные с `--fresh` и сверить `--check`;
4. прописать `LAVA_DB_URL` в `/opt/lava/.env` и поднять стек;
5. тем же адресом переключить сайт и панель.

Откат — убрать `LAVA_DB_URL` из трёх `.env` и поднять стеки заново:
файл SQLite остаётся нетронутым, и игра возвращается к нему как была.

## Боевой сервер

Стоит на той же машине, что и Agile Quest: **159.194.247.90** («Sage Jovana»,
Ubuntu 26.04, 2 CPU, 3.9 ГБ, 34 ГБ свободно), каталог `/opt/lava`. Docker там
уже есть, 80 и 443 держит Caddy для `agilequest.lab260.ru`, высокие порты
провайдер не режет — проверено листенером на 9775 снаружи.

Раздаётся **только сервер**. Клиент игрок приносит свой, и это ровно тот же
пакет из трёх текстовых файлов, что описан выше: `LAVA_HTTP_RES=0`, и ни
одного байта графики с этой машины не уходит.

Но кое-что из клиента серверу нужно самому — он читает оттуда описания
локаций. Всего шесть видов файлов:
`locations/{static,deadloc,desert}/*.xml`, `database/mobs.xml`,
`database/objects.xml`, `avatars/list.xml` — **35 МБ из 2.1 ГБ, 1.7 %**.
Остальное (графика, звук, анимации мобов) сервер не открывает ни разу, и на
сервере ему делать нечего.

```bash
bash deploy/deploy.sh --with-data   # первый раз: код + эти 35 МБ
bash deploy/deploy.sh               # дальше: только код, пересборка, рестарт
```

Таблицы едут отдельным rsync в `/opt/lava/res` белым списком (`--include` по
именам, в конце `--exclude '*'`) и монтируются read-only. В образ не
попадают: пересборка должна гонять мегабайты кода, а не данные, которые не
меняются. База — именованный том, `deploy.sh` её не трогает; `.env` на
сервере создаётся один раз из `deploy/env.example` и при повторных выкладках
не перезаписывается, чтобы адрес, уже разосланный людям, нельзя было сменить
случайно.

### Адрес

**`lava-reborn.ru`** — A-запись на 159.194.247.90. Страница регистрации
и панель идут по HTTPS через тот же Caddy, что держит `agilequest.lab260.ru`:
сертификат Let's Encrypt он выписал сам, как только имя начало резолвиться.
Игровой сокет и порт политики Flash отвечают на том же имени напрямую,
9775 и 843 — HTTP-прокси им не нужен и не подошёл бы.

Блок сайта — [`deploy/Caddyfile.lava`](deploy/Caddyfile.lava). Он проксирует
на **опубликованный порт хоста**, а не в контейнер по имени, и потому стеку
Agile Quest не понадобилось ничего: ни общей docker-сети, ни лишнего тома, ни
пересоздания контейнеров — только строчка в его Caddyfile и `caddy reload` без
перезапуска. Тот же блок закоммичен **и в репозитории Agile Quest**: его
`deploy.sh` синхронизирует `deploy/` целиком, так что правка только на сервере
жила бы до его следующей выкладки.

Что осталось незакрытым: 8080 по-прежнему опубликован наружу, и через него
те же страницы доступны по голому HTTP. Просто закрыть его нельзя — Caddy
ходит именно туда; чтобы убрать, нужна общая сеть с контейнером панели.

## Как это устроено

Клиент сначала грузит `main.swf` и XML-ресурсы по HTTP с `bootstrap_http.py`,
потом открывает XMLSocket на порт 9775. Кадры — текст `команда;ключ=значение;`,
UTF-8, с нулевым байтом в конце; тип значения задаёт первый символ
(`@строка@`, `H`hex, `|список|`, `x`big-uint, цифра — число). Всё описано в
[PROTOCOL.md](PROTOCOL.md).

Три вещи, на которых держится всё остальное, и которые нельзя нарушать:

**Очередь `cmdAck` строго FIFO.** Клиент регистрирует обработчик
подтверждения на часть команд (`EXPECTS_ACK` в `server.py`), и каждый
`cmdAck` достаётся первому в очереди. Лишний или пропущенный ack молча
сдвигает очередь, и все дальнейшие подтверждения уходят чужим обработчикам.
Квестовые запросы идут окном 1, предметные — окном 5: не ответить — клиент
встал навсегда.

**Строки едут числами и должны быть отданы все сразу.** Имена мобов,
предметов, квестов — числовые id, которые клиент разрешает по HTTP через
`texts.xml`. Этот файл в клиенте утрачен (один из двух недостающих из 25 918).
`StringCollector` — вечный синглтон, и любая догрузка строки после входа
перезапускает сцену и выкидывает на экран логина. Поэтому `?all=1` отдаёт всю
таблицу `names.py` целиком, а сервер не отправляет id, которого в ней нет.

**Id локации разрешается правилом клиента.** `locations/static/<id>.xml`
если есть; иначе `id>>28==4` → смерть-локация; иначе `id>>26==0` → пустошь,
где `gx=id>>13, gy=id&0x1FFF`. Пустая клетка карты — сама себе id локации,
поэтому у любой клетки есть куда войти, без единой таблицы. Обе стороны читают
сетку проходимости из выбранного файла: разойтись — значит ходить сквозь стены.

**Стена — это локация, а не пиксель.** Отдельного слоя проходимости в LAVA
не было вовсе: клиент о рельефе глобальной карты не знает ничего, а клетка
закрыта тогда, когда у стоящей на ней локации нет выхода в эту сторону —
кода стороны в узле `outzones`. Все одиннадцать шаблонов пустоши несут
`1234`, поэтому клетка, которой сервер не назвал файла, открыта во все
четыре стороны. Разбор — [recon/analysis/borders.md](recon/analysis/borders.md).

Проходимость какое-то время выводилась из фотографии карты
(`data/build_terrain.py`, шероховатость тайлов `res/globalmap/full`), и это
было неверно: она закрывала 6130 клеток, каждая из которых открылась бы
обычной пустошью с четырьмя выходами, и спорила с 18 из 949 выходов, которые
объявляют сами файлы посёлков. От той таблицы осталась **вода** — единственное,
что фотография находит надёжно (синий выше красного — озеро Насер), 1568
клеток из 273 632, и ни один известный выход в неё не ведёт.

**Край мира — кольцо скал.** В `res/locations/static` лежит полный набор
скальных плиток: четыре стороны по два варианта, четыре угла, четыре
кармана-тупика, два прохода, остров и озеро, все `war=1`, заголовок «Скалы».
Стена каждой — та сторона, кода которой нет в её `outzones`; имена файлов
указывают в другую сторону (`B_LeftSide` закрыт с востока), поэтому плитки
выбираются только по данным. `data/build_borders.py` раскладывает их по
периметру `5833..6335 × 1600..2143` (2088 клеток; две клетки периметра заняты
посёлками, и те наружу не выпускают), `world.location_at` читает эту таблицу
после посёлков и перед пустошью. Запад и север — слово самого клиента:
подписи «Западные Предгорья» и «Северные Предгорья» и ни одного выхода
наружу. Восток и юг раньше стояли по описанному прямоугольнику подписей, а
тамошние посёлки выходы наружу имеют, поэтому они отодвинуты до последней
нарисованной клетки: дальше клиенту нечего показать.

Сервер держит это сам: `world.passable` (вода и прямоугольник), `travel.walk`
(обрезка луча по клеткам), `move_on_map` (ведёт до последней проходимой
клетки и подтверждает остановку кадром) и `travel.plan_exit`, который не
спорит с файлом локации: сторона есть — игрок идёт, а если идти некуда,
открывается карман скал, а не окно ошибки.

Три вывода, которые определяют объём работы:

1. **Клиент — чистый рендерер.** Ни одной боевой формулы он не считает: урон,
   крит, попадание приходят готовыми числами. Баланс можно проектировать
   свой, обязательство одно — самосогласованность.
2. **Баланс во многом сохранился.** Вики `lava-online.fandom.com` жива, её
   таблицы ТТХ списаны прямо с игрового тултипа и ложатся на схему `ss_si_*`
   один в один; страница «Игромеханика» — перепечатка серверных формул.
3. **Невосстановимо только серверное:** HP/урон/ИИ/респаун мобов, шансы лута,
   граф переходов между интерьерами (`serverdata` вычищен во всех 1381 файле),
   реплики НПС. Это проектируется, а не реверсится.

## Инструменты и грабли

Отладка клиента: `LAVA_DEBUG=1` даёт projector с трассировкой в
`%APPDATA%\Macromedia\Flash Player\Logs\flashlog.txt`. HTTP-лог
`logs/http.log` — первое место, куда смотреть, если что-то не нарисовалось:
404 на ресурс означает чёрный экран без единой ошибки в клиенте. Если
`database/locations.xml` в нём запрошен больше одного раза — цепочка строк
прокрутилась повторно, ищи id мимо таблицы.

Декомпиляция: JPEXS FFDec 26.3, Java 8. Исходники в `recon/as-src` — это
фактически код клиента с оригинальными именами; любой вопрос «что клиент
ждёт» решается чтением, а не угадыванием.

Среда: Python только в WSL (`wsl.exe -e python3`); Git Bash подменяет пути в
аргументах `wsl.exe` (`MSYS_NO_PATHCONV=1`); heredoc в Bash съедает `\\` —
патч-скрипты писать без обратных слешей.
