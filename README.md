# LAVA Online — восстановление сервера

Серверная часть для мёртвой российской MMO **LAVA Online** (VR-Ocean, 2008–2018).
Клиент — Flash/ActionScript 2, официальные серверы выключены, домены не
резолвятся. Здесь пишется **только сервер**; клиент не модифицируется и не
распространяется, игрок приносит свою копию.

Состояние на 16 сентября 2026: настоящий клиент под Flash Player projector
регистрируется, входит, ходит по чёрному рынку Вади-Хальфы среди жителей с
настоящими именами, выходит на глобальную карту, летает по ней и заходит в
любую клетку — 77 восстановленных посёлков или пустошь. Несколько игроков
видят друг друга, ходят и переписываются (комнаты, приват, мировой канал).
У персонажа настоящие характеристики: атрибуты, навыки, специализации с
обучением у учителя, опыт и деньги. Инвентарь: покупка у торговцев, слоты,
зарядка оружия — с сохранением. Шесть квестов на рынке, лекарь, прописка.
Сервер останавливается мягко, сохраняя всех. Боя пока нет — он в работе.

Полный разбор клиента по подсистемам и план «нормального» сервера — в
[TASKS.md](TASKS.md) и `recon/analysis/`.

## Запуск

Нужны: Windows с WSL (серверы крутятся там, Python только WSL-овский), клиент
в `~/Desktop/LAVA`, Flash Player projector 32.0.0.465 в `tools/flash/`
(качается с `fpdownload.macromedia.com/pub/flashplayer/updaters/32/flashplayer_32_sa.exe`).

```bash
./run.sh            # серверы + клиент
./run.sh servers    # только серверы
./run.sh stop
./run.sh log        # хвост logs/game.log
```

Регистрация — в браузере на `http://127.0.0.1:8080/`. Тестовый аккаунт
`polestvr` / `lava1234`.

Тесты (тринадцать серверных наборов и два по данным, все обязаны быть
зелёными перед коммитом):

```bash
cd server && for t in test_protocol test_accounts test_handshake test_locations test_world test_bootstrap test_shutdown test_progression test_inventory test_two_clients test_quests test_social test_items; do python3 $t.py || break; done
python3 data/test_wiki_data.py && python3 data/test_world_data.py
```

Переменные: `LAVA_GX`/`LAVA_GY` — стартовая клетка карты (5970×1730),
`LAVA_LOC` — принудительный id локации, `LAVA_DEBUG=1` — отладочный projector
с `flashlog.txt`, `LAVA_PLAYER=ruffle` — Ruffle (рисует интерфейс в 313×107,
непригоден).

Команды чата, наши, не игры: `/where` — где стою (название, файл, клетка),
`/goto <id>` или `/goto <x> <y>` — переход в любую из 1381 локации.

## Как это устроено

Клиент сначала грузит `main.swf` и XML-ресурсы по HTTP с `bootstrap_http.py`,
потом открывает XMLSocket на порт 9775. Кадры — текст `команда;ключ=значение;`,
UTF-8, с нулевым байтом в конце; тип значения задаёт первый символ
(`@строка@`, `H`hex, `|список|`, `x`big-uint, цифра — число). Всё описано в
[PROTOCOL.md](PROTOCOL.md).

Три вещи, на которых держится всё остальное, и которые нельзя нарушать:

**Очередь `cmdAck` строго FIFO.** Клиент регистрирует обработчик
подтверждения на часть команд (`EXPECTS_ACK` в `server.py`), и каждый
`cmdAck` достаётся первому в очереди. Лишний или пропущенный ack молча
сдвигает очередь, и все дальнейшие подтверждения уходят чужим обработчикам.
Квестовые запросы идут окном 1, предметные — окном 5: не ответить — клиент
встал навсегда.

**Строки едут числами и должны быть отданы все сразу.** Имена мобов,
предметов, квестов — числовые id, которые клиент разрешает по HTTP через
`texts.xml`. Этот файл в клиенте утрачен (один из двух недостающих из 25 918).
`StringCollector` — вечный синглтон, и любая догрузка строки после входа
перезапускает сцену и выкидывает на экран логина. Поэтому `?all=1` отдаёт всю
таблицу `names.py` целиком, а сервер не отправляет id, которого в ней нет.

**Id локации разрешается правилом клиента.** `locations/static/<id>.xml`
если есть; иначе `id>>28==4` → смерть-локация; иначе `id>>26==0` → пустошь,
где `gx=id>>13, gy=id&0x1FFF`. Пустая клетка карты — сама себе id локации,
поэтому вся карта проходима без таблиц. Обе стороны читают сетку проходимости
из выбранного файла: разойтись — значит ходить сквозь стены.

## Что известно о клиенте

Разбор 395 классов по восьми направлениям лежит в `recon/analysis/`. Коротко:

| Отчёт | Главное |
|---|---|
| [protocol.md](recon/analysis/protocol.md) | 53 команды клиента, 90 сетевых сообщений сервера. Реализовано 10 / заглушек 10 / нет 33. Матрица ack-ожиданий и где текущий сервер её нарушает |
| [architecture.md](recon/analysis/architecture.md) | Ревизия прототипа, целевая структура модулей, DDL, миграция в 8 шагов без остановки входа, тест на два сокета |
| [world.md](recon/analysis/world.md) | Мультиплеер: `id=0` — всегда «я»; чужой игрок через `lch;rtype=-1`; карта с heartbeat ≤3 с. Сторона выхода закодирована в `outzones`. Чат, почта, отряд, кланы, поля боя |
| [combat.md](recon/analysis/combat.md) | Бой — одна команда `ss_use`, ответ строго `faAim → N×(faShot/faHit) → usrUp → c_ap`. Формулы с вики «Игромеханика» — это дизайн-док разработчиков |
| [items.md](recon/analysis/items.md) | `oid = <uniq><type:4><root:2>`, 6+2+рюкзак, коды слотов, все сессии с НПС до кадра, коды ошибок |
| [quests.md](recon/analysis/quests.md) | Дерева диалогов нет; квест = `q_si_{kill_mobs\|bring_l_obj\|del_obj}` + `q_di_*`; 1191 квест снят с вики в `wiki_quests_all.json` |
| [progression.md](recon/analysis/progression.md) | Свободных очков нет: атрибуты растут со спецами, навыки — опытом за действия. Пороги, HP, ОД восстановлены с вики. Формулы `CharInterface.as` дословно |
| [data.md](recon/analysis/data.md) | Что в `res/`, что на вики (4016 статей), мост вики↔клиент по именам иконок, что невосстановимо |

Три вывода, которые определяют объём работы:

1. **Клиент — чистый рендерер.** Ни одной боевой формулы он не считает: урон,
   крит, попадание приходят готовыми числами. Баланс можно проектировать
   свой, обязательство одно — самосогласованность.
2. **Баланс во многом сохранился.** Вики `lava-online.fandom.com` жива, её
   таблицы ТТХ списаны прямо с игрового тултипа и ложатся на схему `ss_si_*`
   один в один; страница «Игромеханика» — перепечатка серверных формул.
3. **Невосстановимо только серверное:** HP/урон/ИИ/респаун мобов, шансы лута,
   граф переходов между интерьерами (`serverdata` вычищен во всех 1381 файле),
   реплики НПС. Это проектируется, а не реверсится.

## Инструменты и грабли

Отладка клиента: `LAVA_DEBUG=1` даёт projector с трассировкой в
`%APPDATA%\Macromedia\Flash Player\Logs\flashlog.txt`. HTTP-лог
`logs/http.log` — первое место, куда смотреть, если что-то не нарисовалось:
404 на ресурс означает чёрный экран без единой ошибки в клиенте. Если
`database/locations.xml` в нём запрошен больше одного раза — цепочка строк
прокрутилась повторно, ищи id мимо таблицы.

Декомпиляция: JPEXS FFDec 26.3, Java 8. Исходники в `recon/as-src` — это
фактически код клиента с оригинальными именами; любой вопрос «что клиент
ждёт» решается чтением, а не угадыванием.

Среда: Python только в WSL (`wsl.exe -e python3`); Git Bash подменяет пути в
аргументах `wsl.exe` (`MSYS_NO_PATHCONV=1`); heredoc в Bash съедает `\\` —
патч-скрипты писать без обратных слешей.
