# LAVA Online — восстановление сервера

Серверная часть для мёртвой российской MMO **LAVA Online** (VR-Ocean, 2008–2018).
Клиент — Flash/ActionScript 2, официальные серверы выключены, домены не
резолвятся. Здесь пишется **только сервер**; клиент не модифицируется и не
распространяется, игрок приносит свою копию.

Состояние на 18 сентября 2026: настоящий клиент под Flash Player projector
регистрируется, входит и играет. Несколько игроков видят друг друга, ходят,
переписываются в каналах и приватом, собираются в отряд и шлют письма с
деньгами и вложениями. У персонажа настоящие характеристики: атрибуты,
навыки, специализации с обучением у учителя, опыт, деньги. Инвентарь:
покупка и продажа у торговцев, слоты, зарядка оружия — всё с сохранением.
Бой: выстрел и удар по кадрам оригинала, очки действия, мобы с ИИ, лут и
смерть — с потерей вещи из рюкзака, тремя видами возрождения и переносом на
место прописки; мёртвым можно и войти в игру. Тринадцать квестов, лекарь,
прописка. Глобальная карта
на 262 восстановленные клетки, из локации можно выйти не только на карту,
но и в соседнюю клетку по стороне выхода. Сервер останавливается мягко,
сохраняя всех, кто в игре, и поднимается в docker — друзьям отдаётся адрес и
папка из трёх текстовых файлов, ресурсы игры каждый приносит свои.

Полный разбор клиента по подсистемам и план «нормального» сервера — в
[TASKS.md](TASKS.md) и `recon/analysis/`.

## Запуск

Нужны: Windows с WSL (серверы крутятся там, Python только WSL-овский), клиент
в `~/Desktop/LAVA`, Flash Player projector 32.0.0.465 в `tools/flash/`
(качается с `fpdownload.macromedia.com/pub/flashplayer/updaters/32/flashplayer_32_sa.exe`).

```bash
./run.sh            # серверы + клиент
./run.sh servers    # только серверы
./run.sh stop
./run.sh log        # хвост logs/game.log
```

Регистрация — в браузере на `http://127.0.0.1:8080/`. Тестовый аккаунт
`polestvr` / `lava1234`.

Тесты (восемнадцать серверных наборов и шесть по данным, все обязаны быть
зелёными перед коммитом):

```bash
cd server && for t in test_protocol test_accounts test_handshake test_locations test_world test_bootstrap test_shutdown test_progression test_inventory test_two_clients test_quests test_social test_items test_combat test_travel test_terrain_move test_death test_transport; do python3 $t.py || break; done
cd .. && for t in test_wiki_data test_world_data test_settlements test_terrain test_borders test_transport_data; do python3 data/$t.py || break; done
python3 tools/test_export_texts.py
```

Переменные: `LAVA_GX`/`LAVA_GY` — стартовая клетка карты (5970×1730),
`LAVA_LOC` — принудительный id локации, `LAVA_DEBUG=1` — отладочный projector
с `flashlog.txt`, `LAVA_PLAYER=ruffle` — Ruffle (рисует интерфейс в 313×107,
непригоден).

Команды чата, наши, не игры: `/where` — где стою (название, файл, клетка),
`/goto <id>` или `/goto <x> <y>` — переход в любую из 1381 локации,
`/home` — домой (куда прописан у жителя, иначе на старт; тем же путём
пойдёт возрождение), `/give <тип> [сколько]` — предмет в рюкзак,
`/money <афро> [голда в сотых]` — пополнить кошелёк (новичку дают 1000 афро,
а аренда транспорта стоит тысячи в день, иначе её не попробовать руками).

Аренда транспорта: у арендодателя (в Вади-Хальфе это Шихаб на чёрном рынке)
окно «Аренда» показывает, что он сдаёт, срок 1..365 дней и цену за день.
Ослик — 0.1 голды в день и +70 % к скорости на карте, дальше по возрастанию
до Ларвы (+350 %). Пока аренда идёт, `userInfo_Player` несёт `tr`/`tr_hours`,
и перелёты по карте идут быстрее ровно во столько раз. Таблица —
`data/transport.json`, провод — `server/transport.py`.

### Что происходит, когда убивают

HP до нуля — и фигура падает там, где стояла: соседи видят труп, автоогонь
и мобы сбрасывают его с цели, а сам игрок получает окно возрождения. Пока
оно открыто, сервер не принимает от него ничего, кроме возрождения (ходить,
стрелять, уйти на карту и даже поговорить в чат нельзя), но на запросы вроде
«покажи рюкзак» по-прежнему отвечает — иначе у клиента навсегда закроется
очередь этих запросов. Из рюкзака на месте гибели остаётся один незакреплённый
предмет из тех, что вики помечает «выпадает при смерти»: обычный мешок, любой
может подобрать.

Смерть переживает выход из игры: вошедший мёртвым так и войдёт мёртвым, и
клиент сам поднимет ему то же окно (`persInfo;death=1`).

В окне три кнопки, и они разные:

| Кнопка | Цена | Итог |
|---|---|---|
| Бесплатно | подождать 15 с (окно само нажмёт её, когда отсчёт кончится) | четверть HP, ноль выносливости |
| 5 голды | 5 голды | HP и выносливость целиком, сразу |
| 500 афро | 500 афро (те же 5 голды по курсу сервера) | HP и выносливость целиком, сразу |

Возрождение **всегда** переносит на место прописки (`on_conv;op=0` у жителя
с `can_set_home`), а без прописки — в стартовую локацию. На месте гибели не
оставляет никогда. Проверить дорогу, не умирая, можно командой `/home` — из
боя она, как и выход на карту, откажет.

Выход из локации «в другую локацию» (`chWorld;to=1`) работает по стороне
клетки выхода: стороны W/N/E/S ведут в соседнюю клетку карты с прибытием на
противоположный край, двери a/b — в интерьер из `data/exits.json`, если цель
известна хотя бы со средней уверенностью, иначе отказ строкой в чат. По краю
мира (5833..6335 × 1600..2143) стоит кольцо скал: у этих файлов нет выхода
наружу, поэтому за карту не выйти, а сам край — это место, куда доходишь.
Где путь всё-таки кончается (озеро), открывается «карман» — тупиковая
скальная сцена с единственным выходом назад. Всё это — `server/travel.py`.

## Раздача: docker и пакет игрока

Всё выше — разработка на одной машине, через `run.sh`. Чтобы позвать друзей,
поднимается то же самое в docker, а игроку отдаётся папка из трёх текстовых
файлов. **Ресурсы игры не раздаются**: клиент у игрока свой, и ни один файл
из `res/` не уходит ни в образ, ни на HTTP.

Работает это потому, что клиент, запущенный с диска, в сеть почти не ходит.
Он пробует загрузить `xmldocs/csettings_v1.xml`, не находит его (в выпущенном
клиенте этого файла нет) и переходит в режим LOCAL: графика, звук, локации,
аватары — всё с диска, адрес сервера — из флешваров `var_host`/`var_port`, а
по сети остаётся один игровой сокет. Полный разбор со ссылками на строки
исходников — [`recon/analysis/local-mode.md`](recon/analysis/local-mode.md).

### Подъём

```bash
cp .env.example .env         # и поправить LAVA_RES_DIR и LAVA_PUBLIC_HOST
docker compose up -d --build
docker compose logs -f game
docker compose down          # SIGTERM доходит до сервера, всех сохраняет
```

Два сервиса из одного образа: `game` — игровой сокет, `http` — страница
регистрации. Разделены потому, что останавливать надо именно сервер, а
`docker stop` шлёт сигнал одному процессу.

| переменная | по умолчанию | что делает |
|---|---|---|
| `LAVA_RES_DIR` | — (обязательна) | папка `res/` игрока, монтируется read-only; сервер читает из неё локации, `database/mobs.xml` и `objects.xml` |
| `LAVA_PUBLIC_HOST` | `127.0.0.1` | адрес, который страница регистрации показывает игрокам |
| `LAVA_GAME_PORT` | `9775` | опубликованный порт игрового сокета |
| `LAVA_HTTP_PORT` | `8080` | опубликованный порт страницы регистрации |
| `LAVA_BIND` | `0.0.0.0` | на каком интерфейсе публиковать; `127.0.0.1` — только через туннель |
| `LAVA_LOG_LEVEL` | `INFO` | `DEBUG` — провод в лог |
| `LAVA_HTTP_RES` | `0` | раздавать ли `/res/**` по HTTP. **Ноль — это и есть смысл затеи**: раздача включает и `csettings_v1.xml`, а он переводит клиент в режим WEB, то есть на загрузку всего с сервера |
| `LAVA_POLICY_PORT` | `0` | порт политики Flash; 843 привилегированный, а образ работает без прав, и политика всё равно отвечается прямо в игровом сокете |

База — именованный том `lava-db`, не bind-mount: на диске Windows,
примонтированном в WSL, sqlite не может взять блокировки WAL и молча
откатывается к журналу, где два процесса начинают мешать друг другу
(TASKS 1.2). Healthcheck: у `game` — рукопожатие политики в игровом сокете, у
`http` — `GET /status`.

Страница регистрации ни при выключенной раздаче, ни при включённой ничего из
`res/` не берёт — она целиком в `bootstrap_http.PAGE`; это проверяется в
`test_bootstrap.py`.

### Пакет игрока

```bash
LAVA_RES=/путь/к/res python3 tools/make_client_package.py \
    --host lava.example.org --port 9775 --http-port 8080
```

Кладёт в `dist/` три файла и ничего больше:

* `texts.xml` — таблица строк, которую игрок копирует к себе в
  `res/database/`. Это один из двух файлов, которых в выпущенном клиенте нет
  (второй — `hints/hints.xml`, без него просто не будет подсказок). Инвариант
  PROTOCOL §9 в режиме LOCAL никуда не девается: в файле должны быть **все**
  id, которые сервер может прислать, иначе догрузка одной строки после входа
  вернёт игрока на экран логина. `tools/export_texts.py` это проверяет, а
  `tools/test_export_texts.py` — что файл совпадает байт в байт с тем, что
  `bootstrap_http` отдаёт на `?all=1`.
* `lava.bat` — запускалка с подставленным адресом. Флешвары едут в строке
  запроса к `main.swf`: своего ключа командной строки у projector нет.
  Копирует `texts.xml` на место при первом запуске.
* `README.txt` — по-русски: куда что положить, где взять projector, как
  войти.

**Что игрок приносит сам:** свою копию `res/` и Flash Player projector 32
(`fpdownload.macromedia.com/pub/flashplayer/updaters/32/flashplayer_32_sa.exe`).
Дальше — регистрация на `http://<адрес>:8080/` и `lava.bat`.

Если флешвары почему-то не доехали, это не тупик: поля адреса и порта есть в
самом окне входа, и клиент соединяется именно с тем, что в них написано
(`EnterGameInterface.as:162-163`, `:234-235`). В `README.txt` пакета про это
сказано.

```
PROTOCOL.md          протокол: кадры, типы, очередь cmdAck, инварианты, строки, локации
ROADMAP.md           первые находки: клиент — рендерер, баланс на вики, инварианты
TASKS.md             план работ с приоритетами, собран из recon/analysis
```

Ресурсы клиента (`res/`, 2.1 ГБ) в репозиторий **не кладутся** — это
собственность правообладателя. Сервер читает их с диска.

## Как это устроено

Клиент сначала грузит `main.swf` и XML-ресурсы по HTTP с `bootstrap_http.py`,
потом открывает XMLSocket на порт 9775. Кадры — текст `команда;ключ=значение;`,
UTF-8, с нулевым байтом в конце; тип значения задаёт первый символ
(`@строка@`, `H`hex, `|список|`, `x`big-uint, цифра — число). Всё описано в
[PROTOCOL.md](PROTOCOL.md).

Три вещи, на которых держится всё остальное, и которые нельзя нарушать:

**Очередь `cmdAck` строго FIFO.** Клиент регистрирует обработчик
подтверждения на часть команд (`EXPECTS_ACK` в `server.py`), и каждый
`cmdAck` достаётся первому в очереди. Лишний или пропущенный ack молча
сдвигает очередь, и все дальнейшие подтверждения уходят чужим обработчикам.
Квестовые запросы идут окном 1, предметные — окном 5: не ответить — клиент
встал навсегда.

**Строки едут числами и должны быть отданы все сразу.** Имена мобов,
предметов, квестов — числовые id, которые клиент разрешает по HTTP через
`texts.xml`. Этот файл в клиенте утрачен (один из двух недостающих из 25 918).
`StringCollector` — вечный синглтон, и любая догрузка строки после входа
перезапускает сцену и выкидывает на экран логина. Поэтому `?all=1` отдаёт всю
таблицу `names.py` целиком, а сервер не отправляет id, которого в ней нет.

**Id локации разрешается правилом клиента.** `locations/static/<id>.xml`
если есть; иначе `id>>28==4` → смерть-локация; иначе `id>>26==0` → пустошь,
где `gx=id>>13, gy=id&0x1FFF`. Пустая клетка карты — сама себе id локации,
поэтому у любой клетки есть куда войти, без единой таблицы. Обе стороны читают
сетку проходимости из выбранного файла: разойтись — значит ходить сквозь стены.

**Стена — это локация, а не пиксель.** Отдельного слоя проходимости в LAVA
не было вовсе: клиент о рельефе глобальной карты не знает ничего, а клетка
закрыта тогда, когда у стоящей на ней локации нет выхода в эту сторону —
кода стороны в узле `outzones`. Все одиннадцать шаблонов пустоши несут
`1234`, поэтому клетка, которой сервер не назвал файла, открыта во все
четыре стороны. Разбор — [recon/analysis/borders.md](recon/analysis/borders.md).

Проходимость какое-то время выводилась из фотографии карты
(`data/build_terrain.py`, шероховатость тайлов `res/globalmap/full`), и это
было неверно: она закрывала 6130 клеток, каждая из которых открылась бы
обычной пустошью с четырьмя выходами, и спорила с 18 из 949 выходов, которые
объявляют сами файлы посёлков. От той таблицы осталась **вода** — единственное,
что фотография находит надёжно (синий выше красного — озеро Насер), 1568
клеток из 273 632, и ни один известный выход в неё не ведёт.

**Край мира — кольцо скал.** В `res/locations/static` лежит полный набор
скальных плиток: четыре стороны по два варианта, четыре угла, четыре
кармана-тупика, два прохода, остров и озеро, все `war=1`, заголовок «Скалы».
Стена каждой — та сторона, кода которой нет в её `outzones`; имена файлов
указывают в другую сторону (`B_LeftSide` закрыт с востока), поэтому плитки
выбираются только по данным. `data/build_borders.py` раскладывает их по
периметру `5833..6335 × 1600..2143` (2088 клеток; две клетки периметра заняты
посёлками, и те наружу не выпускают), `world.location_at` читает эту таблицу
после посёлков и перед пустошью. Запад и север — слово самого клиента:
подписи «Западные Предгорья» и «Северные Предгорья» и ни одного выхода
наружу. Восток и юг раньше стояли по описанному прямоугольнику подписей, а
тамошние посёлки выходы наружу имеют, поэтому они отодвинуты до последней
нарисованной клетки: дальше клиенту нечего показать.

Сервер держит это сам: `world.passable` (вода и прямоугольник), `travel.walk`
(обрезка луча по клеткам), `move_on_map` (ведёт до последней проходимой
клетки и подтверждает остановку кадром) и `travel.plan_exit`, который не
спорит с файлом локации: сторона есть — игрок идёт, а если идти некуда,
открывается карман скал, а не окно ошибки.

Три вывода, которые определяют объём работы:

1. **Клиент — чистый рендерер.** Ни одной боевой формулы он не считает: урон,
   крит, попадание приходят готовыми числами. Баланс можно проектировать
   свой, обязательство одно — самосогласованность.
2. **Баланс во многом сохранился.** Вики `lava-online.fandom.com` жива, её
   таблицы ТТХ списаны прямо с игрового тултипа и ложатся на схему `ss_si_*`
   один в один; страница «Игромеханика» — перепечатка серверных формул.
3. **Невосстановимо только серверное:** HP/урон/ИИ/респаун мобов, шансы лута,
   граф переходов между интерьерами (`serverdata` вычищен во всех 1381 файле),
   реплики НПС. Это проектируется, а не реверсится.

## Инструменты и грабли

Отладка клиента: `LAVA_DEBUG=1` даёт projector с трассировкой в
`%APPDATA%\Macromedia\Flash Player\Logs\flashlog.txt`. HTTP-лог
`logs/http.log` — первое место, куда смотреть, если что-то не нарисовалось:
404 на ресурс означает чёрный экран без единой ошибки в клиенте. Если
`database/locations.xml` в нём запрошен больше одного раза — цепочка строк
прокрутилась повторно, ищи id мимо таблицы.

Декомпиляция: JPEXS FFDec 26.3, Java 8. Исходники в `recon/as-src` — это
фактически код клиента с оригинальными именами; любой вопрос «что клиент
ждёт» решается чтением, а не угадыванием.

Среда: Python только в WSL (`wsl.exe -e python3`); Git Bash подменяет пути в
аргументах `wsl.exe` (`MSYS_NO_PATHCONV=1`); heredoc в Bash съедает `\\` —
патч-скрипты писать без обратных слешей.
