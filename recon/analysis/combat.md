## 1. Полный цикл выстрела и удара

### 1.1 Что шлёт клиент: `ss_use`

Единственная боевая команда клиент→сервер — `ss_use` (`CSM_SSUse.as`):

    ss_use;type=<acID>;obj=x<oid>;target=x<цель>;

Порядок ключей на проводе не важен (сервер парсит по имени). Значения:

- `type` — идентификатор действия, **бит** из `action_map` предмета
  (`Item.as:312-333`: `acID = 1 << i`):

  | Действие | константа `Item.as:48-55` | `type` на проводе |
  |---|---|---|
  | зарядить | LOAD=0 | 1 |
  | использовать без цели (лечить себя, съесть) | USE_IDLE=1 | 2 |
  | использовать на живую цель (лечить другого) | USE_TARGET=2 | 4 |
  | использовать на предмет | USE_ITEM=3 | 8 |
  | стрельба **и удар** | FIRE=4 | 16 |
  | разрядить | UNLOAD=5 | 32 |
  | смена режима огня | USEMODE=6 | 64 |
  | удалить предмет | DELETE=0 (сырой ноль, `ItemActivator.as:25-34`) | 0 |

  Для удара `type=16` захардкожен (`ItemActivator.as:136`), для выстрела берётся
  `actions[FIRE].acID` (`:94`) — то есть в `action_map` огнестрела бит 16 обязан
  быть выставлен, иначе клиент не пошлёт ничего.
- `obj` — oid предмета как BigUINT: `"x" + hex(oid)` (`BigUINT.as:59-73`).
  Для кулака `obj=x0` (`ItemActivator.as:137`: у «кулака» oID = 0).
- `target` — тоже BigUINT, собранный `MDString.createBigUINT([targetType,1],[target,8])`
  (`ItemActivator.as:89,133`): одна hex-цифра типа цели + id, дополненный
  нулями до 8 hex-знаков:
  - `x1` + `0000002a` → `target=x10000002a` — цель = сущность с id 42;
  - `x0` + `00000f3c` → `target=x000000f3c` — цель = гекс № 3900
    (`fireHex`/`strikeHex`, `CursorManager.as:407-412, 463-467`);
  - при зарядке `target=x<oid патронов>` (`ItemActivator.as:47-52`);
  - при смене режима `target=<0|1|2>` — просто число, не BigUINT (`:169`);
  - при лечении другого `target=x1<id>` (`Gamer.as:283`), себя — без `target`.

  Парсер клиента хранит `x`-значения строкой без префикса (`SCDataParser.as:140-144`);
  серверный `protocol.py` уже отдаёт их как `BigUInt` (`protocol.py:31,159-161`).

Клиентские предпроверки до отправки (`ItemActivator.as:70-149`):
1. `locInfo.battle` — атрибут `war="1"` XML-локации (`LDParser.as:21`). В мирной
   локации выстрел/удар не уходит вовсе («В этой локации Вы не можете вести
   боевые действия»).
2. Цель-игрок в локации с `pvp="0"` (`LDParser.as:23`) — отказ.
3. `ammo_count > 0`, иначе автоперезарядка (`AUTO_RELOAD` по умолчанию `true`,
   `UserSettings.as:83`) и всплывашка «Кончились патроны» (код 13).
4. `canUse()` (`:275-290`): в боевом состоянии (`warStatus`) требует
   `ap >= getAP(type)`; вне боевого состояния ОД **не проверяются вовсе**.
5. `coolDownBlock` (`:189-198`): после отправки следующая `ss_use` блокируется
   до `cmdAck`, до `faShot`/`caHit`/`caMiss` или до 3 с (`breakInterval`).

Регистрируется обработчик `cmdAck` (`:197`) — ровно один ответ, FIFO.

### 1.2 Что ждёт клиент: последовательность кадров сервера

**Шаг A. `cmdAck;res=0;`** — обязателен. `res≠0` → `ItemActivator.useAck`
сбрасывает блокировку и `Gamer.dispatchAck(res)` (`Gamer.as:343-346`) →
`Location.fireFailed` (`Location.as:312-319`) → фигура опускает оружие
(`FIRE_OUT`, `DisplayLocScene.as:349-352`), а `ErrorReport` показывает текст
по коду (`ErrorReport.as:59-81`):

| res | Текст | Когда слать |
|---|---|---|
| 11 | Не хватает очков действия | AP < стоимости |
| 12 | Объект не найден | oid не принадлежит игроку |
| 13 | Кончились патроны | ammo_count = 0 |
| 14 | Патроны не подходят к этому оружию | typeID патрона ∉ `comp_array` |
| 15 | Оружие уже заряжено | зарядка полного магазина |
| 16 | Предмет сломан | break = 0 |
| 17 | Объект не готов | таймер (перезарядка/изготовка) ещё идёт |
| 19 | Нет подходящего предмета | — |
| 45 | Не хватает навыков для использования предмета | need_skills/need_attribs |
| 3 | Сервер не отвечает | сейчас шлёт `server.py:144` на любой `ss_use` |

Для `type=16` при `res=0` ОД **не списываются** на аке (`ItemActivator.as:209-216`):
клиент ждёт `faShot`.

**Шаг B. `faAim;id=<стрелок>;ang=<1..8>;num_shots=<N>;`** (`Location.as:320-329`)
- `id` отсутствует/0 = сам игрок. Для мобов и чужих игроков `id` обязателен.
- `ang` — направление 1..8 по таблице `LocationGrid.as:15-22` (см. 1.6); если
  0/нет, фигура сохраняет прежний поворот (`DisplayLocScene.as:306`).
- `num_shots` — число выстрелов в очереди (по умолчанию 1). Клиент ждёт ровно
  столько пар `faShot` (см. ниже). Обычно `= fire_mods[cur_mode]`.
- Для игрока запускается таймбар изготовки длиной `fire_times[cur_mode]` мс
  (`WeaponPan.as:822-844`); фигура переходит в `FIRE_IN` (изготовка).

**Шаг C. На каждый выстрел k = 1..N:**
1. `faShot;id=<стрелок>;status=1;` (`Location.as:334-345`) — создаёт `FireEvent`,
   гасит таймбар изготовки (`TimeBarEvent.SHOT`). Для игрока в этот момент
   списываются ОД: `ap -= fire_costs[cur_mode]` (`ItemActivator.as:223-230,
   265-270`) — **один раз за очередь** (флаг `useFireArm` сбрасывается).
2. Ноль или больше результатов попадания пули:
   - `faHit;target=<id>;dmg=<N>;sdmg=<N>;crit=<0|1>;` (`Location.as:384-399`) —
     `target` пропущен = игрок. Копится в `FireEvent.hits`, накапливается на
     `walker.damage/sdamage` цели (`LocWalker.as:208-212`). Если участвует игрок
     (стрелок или цель) — запускается «таймер выхода» (см. 1.5). Пуля может
     пробить несколько целей: несколько `faHit` в одной паре допустимы
     (`FireEvent.as:14-23, 37-46`).
   - `faWall;hex=<cell>;` (`:400-404`) — пуля в препятствие/гекс: «бум» на клетке.
   - `faMiss;x=<X>;y=<Y>;` (`:405-410`) — промах в точку; клиент рисует «бум» в
     `px = 40*x`, `py = 40*y*20/46` (`DisplayLocScene.as:483-494`) — координаты
     в **единицах гекса** (`rx, ry`, см. 1.6). Если в очереди не было ни одного
     попадания, в чат событий уходит «Персонаж N промахивается»
     (`DisplayLocScene.as:520-561`).
3. `faShot;id=<стрелок>;status=0;` (`Location.as:346-356`) — конец выстрела:
   `currNumOfShot--`; когда дошёл до 0 → `endOfShot` (`:358-383`): суммарный
   урон по последней цели применяется к HP/SP (`Location.damage` →
   `Entity.damage` `:112-121`), в чат уходит DAMAGE (N=1 или дробовик) либо
   SUMMARY_DAMAGE «произвел N выстрелов и нанес вред X по здоровью и Y по
   выносливости при помощи <оружие>» (`GameEvents.as:45-46`). Флаг крита берётся
   из **первого** попадания (`:380`). Для игрока-стрелка ставится `canAutoFire`
   (`AutoCommandManager.as:81-93`).

Строгие правила порядка:
- `faHit`/`faWall`/`faMiss` **только между** `status=1` и `status=0`: вне пары
  `curFireEvent == null` и обработчик падает.
- Число пар `faShot` обязано совпасть с `num_shots`, иначе `currNumOfShot` не
  дойдёт до 0, урон не применится, а следующий `faAim` затрёт незакрытый
  `FireEvent`.
- `usrUp` с абсолютным HP лучше слать **после** последнего `faShot;status=0`:
  клиент уже вычел урон локально; ранний `usrUp` даст двойное списание до
  следующей синхронизации (`Entity.userUpdate` `:102-111` присваивает `hcur`).

**Шаг D. Синхронизация после очереди:**
- `usrUp;id=<цель>;hcur=;hmax=;scur=;smax=;` — абсолютные значения
  (`Master.as:132-137` → `Entity.userUpdate`). `hmax/smax` можно опускать после
  первого раза (`!obj.param.hmax ? старое`).
- `c_ap;ap=<N>;` — абсолютные ОД стрелка (`APManager.as:17-22`). Именно `c_ap`
  запускает следующий автовыстрел (`AutoCommandManager.as:38-50`): без него
  автоогонь работать не будет.
- `ss_di_firearm;obj=x<oid>;ammo_count=<N>;ammo_type=<typeID>;cur_mode=<m>;break=<b>;max_break_cur=<mb>;`
  — динамика оружия; любые ключи попадают в поля предмета через
  `updateProperties` (`ItemFactory.as:148-154`, `Item.as:271-287`), а
  `WeaponPan.itemUpdate` перерисует счётчик патронов (`WeaponPan.as:332-394`).
  При 0 патронов подсвечивается кнопка перезарядки.

**Шаг E. Смерть цели** — раздел 3. **Лут** — `ss_loot;s_status=1;hex=|<cell>|;`
(`Location.as:501-550`).

### 1.3 Тайминги

| Величина | Откуда | Кто отсчитывает |
|---|---|---|
| Изготовка `fire_times[mode]` мс | `ss_si_firearm` | клиент рисует таймбар от `faAim` до `faShot;status=1` (`WeaponPan.as:822-844`); сервер обязан выдержать такую же паузу между `faAim` и первым `faShot`, иначе бар обрывается раньше/позже |
| Пауза между выстрелами очереди | нет | анимация: каждый `FireEvent` проигрывается по кадру `fire` (`DisplayLocScene.as:379-455`, `Char.as:161-178`); сервер может слать пары `faShot` подряд или с шагом ~150-250 мс |
| Перезарядка `reload_time` мс | `ss_si_firearm` | клиент: бар от `cmdAck;res=0` до `itemUpdate` оружия (`WeaponPan.as:845-858, 913-918`), т.е. сервер шлёт `ss_di_firearm` через `reload_time` после ака |
| Разрядка `reload_time` | то же | `WeaponPan.as:859-869` |
| Удар `strike_time` мс | `ss_si_coldarm` (у кулака 0) | бар от отправки до `caHit`/`caMiss` (`WeaponPan.as:881-890, 903-907`) |
| Лечение `heal_time` мс | `ss_si_heal` | бар до `itemUpdate` лечилки (`ss_di_heal`) или `END_HEAL` (`WeaponPan.as:870-880, 919-924`) |
| Тик ОД | `APManager.dt = 600` (`APManager.as:10`) | клиент и сервер независимо, см. 2 |
| Шаг по гексу | 200 мс (`LocWalker.as:74`) | клиент |
| Таймер выхода из боя | `constants;leave_combat_timeout=` (`GConstatns.as:27`; сервер шлёт 30, `server.py:190`) | клиент показывает, сервер обязан отвечать `cmdAck;res=39` на ранний `chWorld` (`Master.as:157-162`) |
| Автовоскрешение | 15 с (`RegenerationInterface.as:18`) | клиент |

Отмена изготовки: движение стрелка (`userMove;id=<стрелок>`) — клиент
обрывает таймбар (`WeaponPan.as:891-900`) и автоогонь
(`AutoCommandManager.as:51-57`); вики «Основа ПвП» подтверждает, что бег
отменяет прицеливание и ОД не тратятся. Значит сервер должен отменять
запланированный `faShot`, если стрелок пошёл, и не списывать ОД. Также
`breakMv;id=0` сбрасывает `coolDownBlock` (`ItemActivator.as:239-245`).

### 1.4 Удар (кулак, нож)

Клиент: `Gamer.gotoWalker(id,"strike")` (`Gamer.as:125-168`) — подходит на
соседний гекс (в боевой локации `spliceNum=1`, т.е. останавливается за клетку
до цели, `:165`), затем `strike` (`:289-300`) проверяет `isSiblings` и шлёт
`ss_use;type=16;obj=x<oid ножа|0>;target=x1<id>;`. По гексу —
`strikeHex` → `target=x0<cell>`.

Сервер: `cmdAck;res=0;` затем **один** из кадров:
- `caHit;id=<бьющий>;target=<цель>;dmg=;sdmg=;crit=;` (`Location.as:411-441`) —
  клиент сам считает поворот (`getDirection`), анимирует, применяет урон сразу,
  пишет CA_DAMAGE в чат. Игроку-бьющему списывается `strike_cost` ОД
  (`ItemActivator.as:231-238`; кулак = 5, `PersEquip.as:86`); при участии игрока
  стартует таймер выхода.
- `caMiss;id=<бьющий>;hex=<cell>;` (`:442-455`) — промах в клетку.

Проверка соседства на сервере: клетки-соседи по `LocationGrid.getSiblings`
(`LocationGrid.as:68-106`): `(gx±1, gy)`, `(gx, gy±1)`, `(gx + (2*(gy%2)-1), gy±1)`.

- Плавающие числа над головой: `CharInfo.updateState` (`CharInfo.as:583-597`)

- Мёртвая анимация `fireAck` (`Location.as:34`, PROTOCOL §8) — не слать.

### 1.6 Геометрия, которую сервер обязан повторить

`LocationGrid.as:43-44`: реальные координаты гекса `rx = gx + 0.5*(gy % 2)`,
`ry = gy * 0.8660254`. Номер клетки `pos = gy*width + gx`.

- Дистанция (`getHexDistance`, `:169-174`): евклидова по `(rx, ry)`. Это
  число клиент красит: зелёное при `opt_range[m] <= d <= end_opt_range[m]`,
  белое при `d <= max_range[m]`, красное дальше (`CursorManager.as:618-655`).
  Автоогонь проверяет `d <= max_range[0]` (`AutoCommandManager.as:253-281`).
  Сервер обязан считать ту же величину: «оптимальная дистанция» = зона крита.
- Направление `ang` (`getDirection`, `:129-168`): по знакам `dx = rx1-rx0`,
  `dy = ry1-ry0` берётся индекс `k`: dx>0: dy>0→1, dy=0→2, dy<0→3; dx<0:
  dy>0→-1, dy=0→-2, dy<0→-3; затем `angles[k]`: 0→2, 1→1, 2→8, 3→7, 4→6,
  -1→3, -2→4, -3→5 (`:15-22`). (dx=0 даёт `undefined` → фигура не поворачивается.)
- Занятость клеток: в боевой локации клетка с сущностью непроходима
  (`isUnreachible`, `:392-409`); клетки NPC `alwaysBusy` всегда.

## 2. Очки действия

`APManager.as`:
- `lenter;pos=;aspd=;amax=;` → `setAP(dap=aspd, apmax=amax)` (`Master.as:272-279`,
  `APManager.as:39-45`): `aspd` — прирост за тик, `amax` — потолок полоски.
- Тик `setInterval(incAP, 600)` (`:10, 46-59`) работает **только при ws=1**;
  при `ws=0` таймер выключен и `ap = maxAP` (`:23-38`). Обрезка `[0, maxAP]`,
  при уходе ниже 0 — событие `breakAction` (`:60-73`).
- Ходьба: `-1` за гекс на каждом `finishPart` (`:12, 86-89`) — только в
  боевом состоянии (подписка ставится в `warState(1)`).
- Коррекция: `breakMv`/`cor_pos` → `LocWalker.syncPos` (`LocWalker.as:151-185`)
  возвращает/досчитывает ОД за непройденные/лишние клетки.
- `c_ap;ap=<N>;` — абсолютная синхронизация (`:17-22`). Клиент **не отвечает**.
- Стоимости: выстрел `fire_costs[cur_mode]`, зарядка/разрядка `reload_cost`,
  смена режима 0, прочее 10 (`FireArm.as:182-199`); удар `strike_cost`
  (`MeleeWeapon.as:62-66`, кулак 5); лечение `heal_cost` (`HealItem.as:68-71`).
  Момент списания на клиенте: выстрел — на `faShot;status=1`; удар — на
  `caHit/caMiss`; остальное — на `cmdAck;res=0` (`ItemActivator.as:206-238`).
- Карточка персонажа показывает `rp_info.ap_max` + `bonus_od` предметов +
  сет-бонусы + `max_od` эффектов (`CharInterface.as:135-183`); полоска в бою —
  `amax` из `lenter`. Их надо держать согласованными.
- Дизайн-док (вики): **пул ОД = 50 + 5 × максимальный навык**; за ход в бою
  ОД тратятся, стоя — восстанавливаются.

Серверу нужно: состояние `ws` на локацию; счётчик ОД на игрока с тиком 600 мс
только при `ws=1`; списание за гексы `moveTo;path=` и за `ss_use`; отказ `res=11`;
`c_ap` после каждой очереди/удара и при любом расхождении; переключение `ws`
(`lch;ws=1` всем в локации при первом враждебном действии, `lch;ws=0` когда
врагов/агрессии нет — клиент по `ws=0` сбрасывает автоцели и высыпает
накопленные сообщения об опыте, `SpecSkillMessages.as:54-134`).

Сейчас `server.py:283` шлёт `lcall;ws=self.loc.war` — в каждой из 1213 боевых
локаций бой «идёт» всегда, ОД тратятся на ходьбу постоянно.

## 3. Смерть и воскрешение

- Смерть любой сущности: `lch;dead=<id>;` (`Location.as:84-92`,
  `Resurrector.as:46-58`, `ItemActivator.as:246-258`, `AutoCommandManager.as:68-70`).
  Клиент: анимация `die` (`DisplayLocScene.as:577-590`), ник и фокус убираются,
  автоцель сбрасывается; у NPC с квестами закрывается квестовое окно.
- Труп остаётся, пока не придёт `lch;lostUser=<id>;` — тогда фигура тает через
  2 с (`DisplayLocScene.as:163-194`), а `PlayerRegister` держит 1 с прокси
  (`PlayerRegister.as:104-123`).
- Если `dead == 0` (сам игрок): `Resurrector.resurrectGamer` (`:12-18`) →
  `currentState = DEAD_STATE` → фильтр пропускает **только `resurrect`**
  (`FilterManager.as` `createDSFilter`) → окно «regeneration»:
  бесплатно (`res_type=0`), 5 голды (`1`), 500 афро (`2`)
  (`RegenerationInterface.as:13-19, 72-107`); через 15 с автоматически
  бесплатно (`:122-142`).
- `resurrect;res_type=N;` → `cmdAck;res=0;` (`Resurrector.as:19-45`): окно
  закрывается, `dead=false`, состояние `LOCAL_STATE`. `res≠0` — окно остаётся,
  таймер перезапускается.
- Флаг смерти на входе: `persInfo;...;death=1;` (`PersGenerator.as:128`) →
  после `lenter`/`gmap` окно воскрешения откроется само (`Master.as:196-199, 283-286`).
- Клиент сам **никуда не переносит** игрока и не восстанавливает HP: после
  `cmdAck;res=0` сервер обязан либо слать `usrUp` с новым HP на месте, либо
  `lcall` в другую локацию (штатно — «мёртвые» локации: `id>>28==4` →
  `locations/deadloc/<(id>>26)&3>.xml`, все четыре — шаблон «Граница пустоши»,
  `war="1"`, без спавнов, с выходными зонами по периметру) + `lenter` + полный
  `requestInfo`-цикл.
- Что теряется — в клиенте не закодировано. Вики в карточках предметов
  ведёт поле «Шанс выпадения при смерти» (да/нет), т.е. часть предметов
  выпадала. «Основа ПвП»: после выхода из игры персонаж стоит в боевой
  локации ещё 15 минут.
- Для мобов: `lch;dead=<mob>` → через 1-3 с `lch;lostUser=<mob>` → сумка
  `ss_loot;s_status=1;hex=|<cell>|` → респаун новым `lch;newUser=`.

Лут-сессия (`Loot.as`): клик по сумке → `gotoLoot` → `ss_create;s_type=0;target=<cell>;`
→ `cmdAck;res=0` → `ss_get;slot=24;` (8 рюкзак + 16 сессия, `:56-61`) →
`ss_ack;o_list=|x<oid рюкзака>...|x0|x<oid лута>...|;` — `"0"` разделитель
(`:62-103`). Перенос: `ss_upd;s_status=1;obj=x<oid>` (в рюкзак),
`2` (обратно), `3;obj=x0` (всё), `0;obj=x0` (закрыть) → по `cmdAck` на каждый.

## 4. Эффекты и состояния

Механика узкая: только модификаторы характеристик + `immobilize` + `stun`.
Ни голода, ни кровотечения в клиенте нет (`Effect.as:48-114` — полный список
полей).

  списка. Снятие эффекта = новый `e_list` без него. Пустой список
  `effects=|;`.
- Неизвестный тип → клиент шлёт `e_get_si;type=<t>;` (`CSM_E_get_si.as`),
  ждёт `e_si;type=<t>;name=<strID>;work_time=;update_delta=;attribs_mask=;attribs=|..|;skills_mask=;skills=|..|;specs_mask=;specs=|..|;max_hp=;max_sp=;max_od=;critical_probability=;critical_evade=;armor=;mob_exp=;pl_exp=;mob_drop=;pl_drop=;res_icon=;immob=<0|1>;stun=<0|1>;`

  `res/effects/<n>.swf` (есть 1..23).
- Для **своих** эффектов (mobi_id=0) клиент дополнительно шлёт
  `e_get_di;type=<t>;mobi_id=0;` (`EffectsFactory.as:91-106`) и ждёт
  `e_di;type=<t>;mobi_id=0;time=<сек. осталось>;...` (`:115-128`; `time`
  фиксирует `register_time`, `Effect.as:247-256`).
- Окно запросов `e_get_si`/`e_get_di` = 5 в полёте (`packageLength`,
  `EffectsFactory.as:8, 31-56`) — каждый обязан быть отвечен.
- Дебаф (любое отрицательное поле, `isBuff` `:338-417`) → фраза над головой
  «Я хирею!..», «Моя нога-а!», «Меня парализова...» (`:418-456`,

- Влияние на формулы клиента: `armor`, `critical_probability`,

Лечение (`Gamer.heal` `:265-288`, `PersEquip.useHealItem` `:953-985`):

## 5. Мобы

Моб для клиента — та же сущность, что игрок, с `rtype=0` (`Entity.MOB`,
`PlayerRegister.as:63-103`), поэтому **все боевые кадры одинаковы**, просто с
`id=<mob>`.

Появление и описание:
1. `lch;newUser=<id>;pos=<cell>;rtype=<root_type_id>;` (`Location.as:60-70`;
   `refl=1` — зарегистрировать без фигуры). Клиент тут же шлёт
   `getInfo;type=1;id=<id>;lvl=0;` (`Entity.as:44-48`) и — в локации —
   `ss_get;slot=3;target=<id>;` (`Mob.as:19`, `PlayerRegister.as:57-60`).
2. `userInfo;id=;name=<strID>;sex=0;res=<type_id из mobs.xml>;lvl=<N>;ally=0;rep=|0|;bg_rep=0;bg_pen=0;m_idle=|..|;m_detect=|..|;m_attack=|..|;m_run=|..|;m_death=|..|;`
   (`Mob.as:23-32`, `Entity.as:49-87`). `lvl` даёт цветной значок относительного
   уровня ±4 (`CharInfo.as:294-310`, `PersAttributes.compareLevels` `:335-376`).
   Фразы `m_*` клиент **сам не показывает** — `showPhrase` вызывается только
   из чата под головой и для дебафов (`DisplayLocScene.as:67-85`); чтобы моб
   «говорил», сервер шлёт `userMsg;group=0;from=...;entry=@...@` от его имени.
3. `ss_ack;o_list=|x0|x0|x0|x0|x0|x0|x<oid оружия>|x0|;` — на маску 3 клиент
   ждёт 6 слотов одежды + 2 слота рук (`PersEquip.as:115-153, 191-205`).
   Предмет в `primary` определяет набор анимаций: `fist`/`knife`/`pistol`/`rifle`
   (`Char.changeWeapon` `:256-287`, `FireArm.set weapon_type` `:200-226`).
   У ресурсов мобов наборы разные: `dog` — только `fist_*`, `mob-m2`/`m9` —
   fist, knife, pistol, rifle (`res/mobs/<resource>/`). Моб без оружия бьёт
   кулаком; чтобы стрелял, oid его оружия должен быть в `primary`, а тип —
   отвечен на `ss_get_si`. Сейчас `server.py:615-618` отдаёт пустой `o_list`.
4. `usrUp;id=<mob>;hcur=;hmax=;scur=;smax=;` — иначе полоска = hcur/1200.

Движение: `userMove;id=<mob>;path=|c0|c1|...|;` (`Location.as:184-200`), первая
клетка — текущая; 200 мс на гекс. Коррекция `breakMv;id=;pos=;`.

Агрессия: `lch;enemy=<mob>;` красит его и запоминается автоогнём
(`AutoCommandManager.as:58-66`). Атака моба = `faAim;id=<mob>` … или
`caHit;id=<mob>;target=0;...`. Попадание по игроку с `dmg>0` включает
автоответ (`AUTO_SHOT`, по умолчанию выкл., `:94-107`).

Квесты на убийство: `q_di_kill_mobs;...;kill_num=|..|` — счётчики
(`KillMobQuest.as:23-41`); сервер увеличивает и шлёт при смерти моба.

Минимальный серверный ИИ: конечный автомат на моба
(idle → detect в радиусе N гексов → chase: путь по проходимости из
`world.py` + занятость клеток → attack при `d <= max_range` / соседстве с
интервалом `fire_times` и собственным пулом ОД → leash/reset; респаун через T);
HP/уровень/оружие — из имени типа: `m05_BanditShotgun_lvl2`,
`m05_BanditAssaultGunner_lvl3`, `m05_BanditRaider_lvl1`, `mStarvingDog`
(`res/database/mobs.xml`) — суффикс `_lvlN` и слово оружия парсятся регуляркой.

### 7.2 Серверные формулы из дизайн-дока (вики «Игромеханика»)

Копии страниц (wikitext, CC-BY-SA, сняты 2026-09-16):
`recon/analysis/wiki/igromehanika.wikitext`, `osnova_pvp.wikitext`,
`tablica_opyta.wikitext`. Числа ниже — из первой.

**Ближний бой (кулак/нож)**
- Шанс попасть = `49 + навык0*1.25 + спец0*5 + бонусы`.
- Уворот цели = `лов + вос + навык0 + спец0*3 + бонусы`.
- Попали, если `rnd(1..100) <= шанс − уворот`. Не соседние гексы — промах без
  бросков. Кулак: 5 ОД.
- Крит = `лов + навык0*2.5 + спец0*6`; избежание = `(лов+вос)/2 + навык0/4 + спец0`;
  крит, если `rnd(1..100) <= крит − избежание`.
- Урон кулаком = `rnd(сил/2 .. сил*1.5)`; ножом = `rnd(min..max оружия) + сил + бонусы`.
- Некрит: урон уходит в выносливость, остаток (если SP не хватило) — в HP.

**Стрельба**
- Разброс: `МР = (1 + (0.7 − 0.65/20*навык1) + (0.8 − 0.75/5*спец)) * target_size * ammo.acc_mod`;
  случайный угол в этом конусе и симуляция полёта пули по гексам (отсюда
  `faWall` — камни не простреливаются, «Основа ПвП»); размер цели 0.3 м.
  Клиентская «точность» для тултипа: `round(1000*target_size/max_range)/10`
  (`FireArm.as:77-88`).
- Крит **только на оптимальной дистанции** `[opt_range, end_opt_range]`:
  `крит = (A1 + A2)/4 + навык1/4 + спец*2`, где (A1, A2): пистолет
  `(лов*3, вос)`, ПП `(лов*2, вос*2)`, дробовик `(сил*2, вос*2)`, автомат
  `(лов*2, вос*2)`, винтовка `(лов*2, вос*2)`, пулемёт `(сил*3, вос)`;
  избежание = `(лов+вос)/2 + навык1/8 + спец`. (Коэффициенты клиентского
  зеркала другие — 7.1 — это более поздняя версия; брать клиентские, чтобы
  цифра в карточке совпадала с фактом.)
- Урон: вне оптимальной дистанции `rnd(min..max)`; на оптимальной
  `rnd((max−min)/2 + min .. max)`.
- Броня (некрит): `компенсация = max(0, класс_брони − ammo.piercing)`;
  `sdmg = min(урон, компенсация)`; `dmg = урон − sdmg`; нехватка SP переливается
  в HP. Крит: весь урон в HP, броня не считается.
- Пример из дока: урон 100 / броня 60 → 40 в HP, 60 в SP; броня 120 → 0/100.

Уточнение реализации от 2026-10-05, по решению владельца: описание выше
отражает вики, но не объясняет отдельные `st_damage_min/max` в карточке.
На сервере огнестрел теперь бросает два компонента, H и S, по соответствующим
диапазонам оружия. На оптимальной дистанции нижняя граница обоих поднимается
до середины диапазона. При некрите броня переводит часть H в SP, добавляя
её к S; при крите H идёт в HP, S в SP, броня не участвует. Нехватка SP
переносит остаток в HP в обоих случаях. Это принятое правило, не
подтверждённая формула оригинала. См. `combat.split_damage`, `RoomCombat.burst`
и секцию `firearm health and stamina damage` в `test_combat.py`.

- Базовая броня по доку `(лов*3 + вос)/2`, в клиенте `/4` — расхождение,
  клиент новее.

**Опыт**
- За урон по мобу: `k = clamp(lvl_моба − lvl_игрока, −4, 4) + 4`;
  `xp = floor(k * урон)` «пропорционально пулу моба»; половина в навык,
  половина в специализацию; излишек переносится на следующий ранг.
- За лечение: `МО = min(2, hp_max пациента / макс. лечение предмета)`,
  `xp = floor(вылечено * МО)`.
- Пороги навыка (0..20): `100 * 2^lvl` (100, 200, 400 … 104 857 600).
- Пороги специализации (0..5): `1250 * 8^lvl` (1250, 10 000, 80 000, 640 000,
  5 120 000, 40 960 000). +1 спец → +1 связанный атрибут; атрибут ≤ 20 и ≤
  уровня; специализации с 4-го уровня; цены: бесплатно, 1000 афро, 10/50/100/200 голды.

**Пулы и регенерация**
- HP = `сил*4 + тел*20`; SP = `лов*4 + тел*20`; `тел = floor(5 + 0.75*максНавык)`.
  Таблица уровней с вики «Таблица опыта» (HP/SP без бонусов): 1-2 → 120,
  3 → 140, 4 → 160, 5-6 → 180, 7 → 200, 8 → 220, 9-10 → 240, 11 → 260,
  12 → 280, 13-14 → 300, 15 → 320, 16 → 340, 17-18 → 360, 19 → 380, 20 → 400,
  21 → 420 (сходится: 5*20 + 5*4 = 120).
- ОД = `50 + 5*максНавык`. Вес = `30 + сил*2` кг.
- Регенерация раз в минуту: `+тел` HP при HP 30-100%, `+1` при HP < 30%; каждое
  восстановленное HP стоит 1 SP; SP +1/мин. Сервер шлёт это как `usrUp`.
- Лечилки: `heal_min..heal_max`; навык сдвигает минимум к максимуму на
  `навык2*(max−min)/20`; специализация (хирургия при HP пациента < 30%, иначе
  первая помощь) умножает пороги на `(1 + 0.2*спец)`.

### Инварианты, за нарушение которых клиент ломается (сверх PROTOCOL §7)

1. На каждый `ss_use` — ровно один `cmdAck`, раньше любых `fa*`/`ca*`.
2. `faHit/faMiss/faWall` только внутри пары `faShot;status=1` … `status=0`.
3. Число пар `faShot` = `num_shots` из `faAim`; иначе урон не применится и
   следующая очередь испортится.
4. `faAim/faShot` для мобов — с `id`; `faHit` по игроку — без `target` (или 0).
5. `usrUp` цели — после `faShot;status=0`, не раньше.
6. `ss_get;slot=3` (мобы и чужие игроки) → `ss_ack` с 8 элементами
   (`x0` = пусто), в порядке FIFO очереди `ss_ack`.
7. `e_get_si`/`e_get_di` — окно 5, каждый отвечать.
8. `heal;hp;sp` — абсолютные значения, не приращения.
9. В `DEAD_STATE` от клиента придёт только `resurrect`; всё остальное фильтр
   не выпустит — сервер не должен ждать `lenter` без предварительного `lcall`.
10. `lch;ws=` — единственный способ включить/выключить трату ОД; `c_ap` без
    `ws=1` бесполезен (клиент держит `ap = max`).
