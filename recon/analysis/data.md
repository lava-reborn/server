# Инвентаризация данных: что восстановимо, что придётся проектировать

Обследование 2026-09-16. Источники: `res/` клиента (29 840 файлов), три файла
`res/database`, 1381 файл `res/locations/static`, вики `lava-online.fandom.com`
(через MediaWiki API; WebFetch отдаёт 402, поэтому опрос шёл `urllib` из WSL,
как и прежние скрипты в `recon/notes/wiki_*.py`). Все числа ниже посчитаны
скриптами, а не взяты из README/ROADMAP; где расходятся — здесь точнее.

Главные выводы, если читать только один абзац:

1. В клиенте нет **ни одного числа баланса** — ни у предметов, ни у мобов.
   `objects.xml`/`mobs.xml` — только `type_id`, `root_type_id`, `name`
   (+`resource` у мобов). XML в `mobs/`, `personages/` — карты кадров анимаций.
2. Зато локации хранят **13 781 точку спавна с type_id** в 1345 из 1381 файлов.
   54 % точек ссылаются на типы из `mobs.xml`, 28 % — на пустой тип 0, 18 % —
   на 664 типа, которых в `mobs.xml` уже нет (вырезанный контент).
3. Вики жива и структурирована лучше, чем ожидалось: 4016 статей, 1191 квест
   с полными текстами трёх состояний, ТТХ-таблицы у 100 % выборки предметов,
   координаты у 95 % NPC и 97 % квестов.
4. **Мост вики ↔ клиент найден.** Вики загружала иконки под внутренними
   именами клиента: 410 файлов совпадают с `name` из `objects.xml` буква в
   букву, ещё 22 — по префиксу. Через `prop=images` это связывает ~1000 из
   1959 предметных страниц (87 % чертежей, 76 % поясов, 66 % холодного,
   56–61 % лута и квестовых предметов). Слабое место — огнестрел (6 %):
   там иконки названы по-настоящему («Armalite AR-10(t).png»), а в клиенте
   оружие называется `rifle_1_lvl_14`. Для него нужен второй ключ:
   класс + уровень из «Необходимые навыки: Стрельба N» (даёт в среднем 2,4
   кандидата) плюс сравнение иконок по перцептивному хешу.
5. Невосстановимо нигде: HP/урон/агрессия/скорость/опыт мобов, шансы лута,
   респаун, граф переходов между локациями (`serverdata` вычищен во всех
   1381 файлах), приветствия NPC. Это проектируется.

  («Гладиатор», «Убей генерала»).

Атрибуты корня: `title`, `bg`, `bgExt`, `width`×`height`, `dir`, `library`,

`serverdata`**, т.е. цели переходов и серверные параметры вычищены.

* Размеры: 64×128 — 1255, 32×64 — 126. `dir`: Static 841 (ручные),
  Templates 540 (сгенерированные: библиотеки Desert 380, Mountains 102…).
  Библиотек графики 145.
* `pvp`/`war`: pvp=1 828, pvp=0 525; war=1 1213, war=0 168. Комбинации:
  боевая-pvp 826, боевая-без-pvp 359, мирная 166, pvp-мирная 2.
* Заголовков 364 уникальных; 211 файлов с уникальным названием; 255 «Пустошь»,
  43 «Скалы», 40 «Пустыня» (шаблонные).
* **Спавны**: блок `<mobs>` — hex-строка, 8 символов на точку: `xxyy` +
  `type_id` (16 бит). 1345 локаций со спавнами, 13 781 точка, по локации
  0…37 (медиана ~10). 2947 уникальных типов: 2282 есть в `mobs.xml`,
  665 нет. По точкам: 7493 известных (мобов root 0 — 4737, NPC — 2756),
  3800 с типом 0 (пустой слот), 2488 на 664 неизвестных типа

  228 локаций содержат только неизвестные типы, 36 — без спавнов вовсе.
  Самые частые: тип 0 (3800), `sirena` 3295 (711 — сигнализация),

  (в т.ч. 1226 мобов и 1830 обывателей) — квестовые/ивентовые/динамические.
* Проходимость (`obstacles`, 5 симв./клетка), точки входа (`inzones`, 4),
  выходы со стороной (`outzones`, 5; есть у 1357) и боевые входы
  (`warinzones`) — на месте. Куда ведёт выход — нет.

### Предлагаемый алгоритм связки (по убыванию надёжности)

1. **По имени иконки** (авто, точность ~100 %): для каждой предметной страницы
   взять `prop=images`, нормализовать (`re.sub('[^a-z0-9]','')`), сравнить
   с нормализованными `name` из `objects.xml` точно, затем как префикс с
   длиной ≥ 6. Один файл покрывает серию (`_mod00…10`, `_1…_20`): тир
   выбирать по колонке таблицы (I/II/III ↔ `_lvl`/индекс, (A)/(P)/(G) ↔
   `_A_`/`_P`/`_g`, «Mod IX» ↔ суффикс `_mod_*` по отдельной таблице соответствия).
2. **Патроны — по калибру**: 31 страница × 7 колонок ↔ `Ammo_<калибр>_<KS…BB>`.
   Ручная таблица из 12 калибров (`9мм НАТО`→`9mmNato`, `7.62х39мм`→`762x39`,
   `12-й калибр`→`12mm`, `0.45`→`45`, `5.7x28`→`ss190`…), дальше авто.
3. **Огнестрел — класс + уровень + иконка**: категория страницы даёт класс,
   «Необходимые навыки: Стрельба N» — `lvl`; кандидатов 1–4 на пару.
   Разводить перцептивным хешем: отрендерить 10 059 уникальных `ico.swf`
   (JPEXS `ffdec -export image` или Ruffle) в PNG, посчитать pHash, сравнить
   с ~650 иконками 165×60 из вики (они сняты из того же клиента, хеш должен
   совпадать почти точно). Тот же хеш закроет остаток одежды и холодного.
4. **NPC — по координатам и роли**: координаты со страницы → клетка
   (±3) → `settlements` → id локации → её спавны root≠0 → фильтр по роли
   (торговец/апгрейдер/лекарь/арендодатель = root 1/3/5/6, страница говорит
   «Торговля»/«Ремонт»/«Аренда») → обычно 1–3 кандидата; транслит имени как
   подсказка (63 прямых попадания). Остаток — вручную, как сделаны 16 в
   `npc_names.json`.
5. **Локации — по названию с допуском** (132/192), затем по координатам
   вики → клетка → уже привязанная локация. Списки «Мобы» на страницах
   локаций дают названия групп (Новые Колонисты, Секта Люшер) ↔ заголовки
   лагерей `Up_Camp_*`.
6. **Мобы, баффы, транспорт — вручную**: 32 + 60 + 17 страниц, объём малый.
   Мобы клиента названы по-английски (`m05_BanditRaider_lvl2`), сопоставление
   по смыслу и уровню.

Порядок в категориях и id в URL не помогают: вики сортирует по алфавиту,
собственных id у страниц нет, а `type_id` не встречается в текстах вообще
(поиск по `type_id`, `wh_`, `_lvl` — 0 попаданий).
