# client/objects — свои объекты для локаций

Здесь лежат картинки владельца, из которых получаются новые объекты локаций:
флажок, вывеска, дом, костёр с анимацией. Каждая выкатка собирает из них
файлы спрайтов и кладёт в релиз клиента (`client/build.py`, шаг
`gen_custom_objects`, код в `tools/custom_objects.py` и `tools/swfgen.py`).

Объект `c_test_flag` («Тестовый флажок») — образец: он проверяет весь путь от
картинки до релиза, ни одна локация его не ставит.

## Как добавить объект

1. Придумайте id: `c_` и дальше латиница в нижнем регистре, цифры и `_`, до 40
   знаков (`c_well`, `c_sign_bar`). Русское название пишется в `title`.
2. Положите картинки в папку `client/objects/<id>/`: `0.png`, `1.png`, ...
   Одна картинка — неподвижный объект, несколько — анимация.
3. Добавьте запись в `manifest.json`:

   ```json
   "c_well": {
     "title": "Колодец",
     "frames": ["0.png"],
     "anchor": [48, 90],
     "front": [[-1, 0], [0, 0], [1, 0]],
     "footprint": [[0, 0], [1, 0]]
   }
   ```

4. Проверьте: `python3 tools/custom_objects.py check --base client/base.txt --base client/extra.txt`.
   Он скажет, что не так, или напечатает строку на каждый объект.

## Поля записи

| Поле | Что это |
|---|---|
| `title` | название для редактора, любой текст до 80 знаков в одну строку |
| `frames` | имена картинок из папки объекта по порядку; имя может повторяться, тогда картинка вернётся в анимации и в файл попадёт один раз |
| `fps` | для анимации: сколько картинок в секунду, целое 1..25. Игра идёт 25 кадров в секунду, поэтому картинка держится `round(25 / fps)` кадров: 25 → 1, 12 → 2, 5 → 5 |
| `anchor` | точка картинки `[x, y]` в пикселях, которая стоит в центре клетки: обычно «ноги» объекта. Должна лежать внутри картинки |
| `front` | линия глубины: клетки относительно клетки якоря, `[[dx, dy], ...]`. По ней клиент решает, кто кого заслоняет (LDepthManager): у оригинальных объектов это ряд клеток вдоль их нижнего края. По умолчанию `[[0, 0]]` |
| `footprint` | клетки, по которым нельзя ходить, тоже относительно якоря. Пишутся в `<obstacles>` с кодом `f` (стена). По умолчанию пусто |
| `kind` | `sprite` (по умолчанию) или `background` — фон, который клиент повторяет плиткой от угла; у фона одна картинка и нет `anchor`, `front`, `footprint` |
| `note` | заметка для людей, её никто не читает |

Клетки относительно якоря считаются так же, как их считает клиент: смещения
записаны для якоря на чётном ряду, а на нечётном ряду клетка на нечётном
относительном ряду сдвигается на одну вправо. Сетка шестиугольная: клетка
40 × 15 пикселей, нечётные ряды сдвинуты на полклетки.

## Что принимается

- PNG без чересстрочности (interlace) в любых цветах, с прозрачностью или без.
  Прозрачность сохраняется как есть.
- JPEG только baseline (не progressive), RGB или серый: он кладётся в файл
  байт в байт. Подходит для больших непрозрачных картинок.
- Сторона картинки до 2880 пикселей. Все картинки одной анимации одного размера.
- Картинка до 8 МБ, все картинки папки вместе до 32 МБ: эта папка уезжает с
  каждой выкаткой, а шлюз принимает архив до 64 МБ. Крупные файлы кладутся в
  хранилище сервера и `client/extra.txt` (client/README.md).
- В папке объекта только его картинки, и каждая папка есть в `manifest.json`:
  лишний файл или папка останавливают сборку с объяснением.
- id не может совпадать ни в каком регистре с файлом оригинальной игры
  (`client/base.txt`) или с `client/extra.txt`: такой файл подменил бы
  оригинальный. Ни один файл оригинала не начинается на `c_`.

## Что получается в релизе

`locations/libs/sprite/<id>.swf` для `sprite`, `locations/libs/background/<id>.swf`
для `background`. Файл повторяет устройство оригинальных спрайтов игры
(CL_BW.png.swf, a_campfire.png.swf, Oasis.jpg.swf) и собирается одинаково
байт в байт из одних и тех же картинок, поэтому лаунчер перекачивает только
изменённые объекты. В образ сервера эта папка не попадает: `.dockerignore`
пропускает туда только `server/` и `data/`.

## Как поставить объект в локацию

```
python3 tools/custom_objects.py place c_test_flag 30 65
```

напечатает элемент и клетки препятствий:

```
<sprite id="c_test_flag" dx="-14" dy="-70" front="8080" type="ext">1e41</sprite>
obstacles + 1e41f
```

Элемент `<sprite>` вставляется в XML локации рядом с остальными, клетки
дописываются в `<obstacles>`. Несколько копий одного объекта — несколько
клеток подряд в тексте элемента. Свои объекты свободно стоят рядом с
объектами библиотеки локации. Плоская наклейка на земле —
`<bgdecoration id="<id>" dx="X" dy="Y" type="ext" />` с координатами в пикселях,
фон — `<background type="ext" id="<id>" fx="" />`; оба рисуют только первую
картинку.

Сервер должен видеть ту же локацию, что и клиент, иначе препятствия объекта
будут только у игроков. Поэтому XML локации с объектом кладётся в
`data/locations/static/<id>.xml`: оттуда его читает сервер
(`server/world.py`, `static_path`), и те же байты сборка релиза отдаёт
игрокам вместе со строкой в `xml/loc_defs.xml` (README «Боевой сервер»).
В `client/files/` такой файл класть нельзя: его увидят только игроки.

## Когда игроки увидят объект

После выкатки и перезапуска лаунчера. Пока клиент старый, файла объекта у
него нет; локация при этом всё равно откроется, клиент просто не нарисует
отсутствующий объект.

## Проверки

- `python3 tools/test_swfgen.py` — файлы спрайтов, манифест, расстановка; идёт в CI.
- `python3 client/test_client.py` — сборка релиза с объектами; идёт в CI.
- `bash tools/flash_headless/run.sh <локация.xml>` — по желанию: настоящий Flash
  Player 32 из лаунчера рисует локацию с объектами классами самого клиента, без
  окон и без сети (tools/flash_headless/README.md). CI его не запускает.
