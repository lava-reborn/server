# Полная локальная проверка перед пушем

## Текущее решение владельца — 28.10.2026

Сложные проверки карты и полный локальный All сейчас НЕ запускать.
Не требовать исходный res/установку Docker и сканеров ради этого этапа.
Скрипты и новые регрессии сохраняются на будущее. Прежнее правило обязательного
All перед каждым push не применяется к текущему этапу по прямому решению владельца.
Оставшиеся автоматические проверки выполняются GitHub CI после отправки изменений.
В .github/workflows/ci.yml push запускает CI только для main; релизной ветке
нужен pull request. Самостоятельно создавать коммит, push, PR или запускать
CI/деплой это решение не разрешает. После фактического прогона разобрать результат;
не считать неисполненные проверки пройденными. Адресные локальные прогоны сейчас
также не запускать без новой команды пользователя.


Запускать вручную из PowerShell. Скрипт не запускается автоматически
при редактировании и не устанавливает Git hooks. CI на GitHub сохраняется.
Порядок для каждой ветки: актуализировать регрессии → полный локальный
прогон → исправить замечания → разрешённый push → зелёный Actions на
текущем PR/head → разрешённый merge. После изменения кода старый результат
не считать достаточным. Подробное правило закреплено в TESTING.md.
Runner/отчёты/окружение — только для разработки: не копировать в клиент
игрока; сборщик manifest и deploy-фильтр проверяют границу поставки.

## Подготовка

Нужны Python, Docker Desktop в режиме Linux containers, полный `res/`,
Flash Player и исходный `main (1).swf` в родительской папке репозитория.
Docker скачает `python:3.12-slim` и `postgres:16-alpine`, если их ещё нет;
apt/pip внутри CI-контейнера также требуют интернета. Production-ключи не нужны.
Патченный `locations.xml` не является pristine входом для test_map_labels:
не ослаблять тест, при несовпадении предоставить исходные тестовые ресурсы.
Перед полным прогоном runner сверяет карту с хэшами client/base.txt и
записывает несовместимые входы в asset-inputs.json. Он продолжает остальные
проверки для диагностики, но не считает такой прогон полным успехом.
Папка установленной игры после обновлений может содержать закрашенные
плитки/новые подписи; для приёмки нужен отдельный исходный res, который
указывается через -Res. Не заменять ресурсы игроков, не восстанавливать
оригинальные картинки из уже изменённых JPEG и не подгонять эталоны теста.

Для метрик и сканеров установить в выбранный Python:

```powershell
python -m pip install psutil bandit pip-audit
```

Предпочтительно использовать отдельное окружение проверок, чтобы pip-audit
анализировал именно его, а не все посторонние пакеты системного Python:

```powershell
python -m venv .venv-local-checks
.\.venv-local-checks\Scripts\python.exe -m pip install psutil bandit pip-audit
$env:PATH = "$(Get-Location)\.venv-local-checks\Scripts;$env:PATH"
```

Не коммитить это окружение. Дополнительные зависимости отдельных наборов
не скрываются: при их отсутствии возможны ошибки/пропуски, отражённые в отчёте.
Закрыть другие тестовые серверы/Flash, не менять исходники до конца прогона.
Запускать только один полный прогон одновременно. Если исходники были
исправлены после старта, результаты такого запуска диагностические;
после завершения потребуется новый запуск окончательного дерева.

## Полный запуск

```powershell
cd 'D:\Projects\lava-reborn\server'
powershell -NoProfile -ExecutionPolicy Bypass -File tools\run_local_checks.ps1 -Mode All -Res 'D:\lava-reborn\res' -Jobs 1
```

Параметры при других путях:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\run_local_checks.ps1 -Mode All -Res 'D:\путь\res' -Player 'C:\путь\flashplayer_32_sa.exe' -ClientMain 'C:\путь\main (1).swf' -Jobs 1
```

Полный прогон может занять часы. По умолчанию наборы идут по одному:
сокетные тайминги/Flash чувствительны к нагрузке. Jobs можно увеличить,
но сравнивать производительность нужно при одинаковых условиях.
TimeoutSeconds — предел целого native/CI этапа (по умолчанию 6 часов),
внутренние CI-таймауты отдельных наборов остаются прежними.

## Другие режимы

- `-Mode Native`: все наборы server/data/tools/client штатного Python-runner.
- `-Mode CI`: локальные Linux-этапы через те же shell-скрипты, что CI,
  включая три шарда и PostgreSQL; это не запуск удалённого workflow.
- `-Mode Regression`: актуальные 34 адресных набора релиза для быстрых итераций;
  включает ПКМ/нулевые требования, Жозефа и G-части, статусы/вес/аренду, клиент
  и тестовый загрузчик. Это частичный прогон, не замена All.

Сканеры выполняются во всех режимах. Режимы кроме All явно помечаются
частичными и не заменяют обязательный полный прогон перед пушем.
Flash-пробы в Linux могут пропускаться; это считается покрытым только
при успешном выполнении того же набора без пропуска в native-части.
CI-копия использует текущие рабочие файлы, включая незакоммиченные;
монтируемый проект/ресурсы только для чтения, внутри контейнера отдельная копия.

## Результаты

Каждый запуск создаёт уникальную папку `logs/local-checks/дата-время-id/`:

- `report.md`, `report.json`: сводка, ошибки и неполное покрытие.
- `inventory.json`: наборы native, источник списка PostgreSQL и окружение.
- `asset-inputs.json`: отсутствующие/изменённые оригинальные файлы карты.
- `native/report.html`, `native/summary.txt`: отдельные тесты/проверки/время.
- `ci/stages.tsv`, `ci/shards/`, `ci/postgres/`: результаты проверок CI.
- `warnings.json`, `skips.json`: предупреждения и пропущенные проверки.
- `timings.json`: длительности наборов, включая неуспешные попытки.
- `bandit.json`, `pip_audit.json`: все результаты сканеров.
- `linux-ci-container-stats.json`: выборочные CPU/память контейнера CI.
- `*.out`, `*.err`, `ci/*.log`: полные журналы для разбора.

Сканеры могут давать ложные срабатывания, особенно на тестовом коде;
все найденные записи сохраняются и требуют рассмотрения. pip-audit
использует интернет и анализирует текущее Python-окружение, не Docker-образ.
Отчёт не является исчерпывающим аудитом безопасности.

Коды: 0 — всё выполнено без отмеченных проблем, можно рассматривать результат;
1 — ошибки/находки безопасности; 2 — неполный прогон/предупреждения/нужен разбор.
Даже код 0 не является автоматическим разрешением push/deploy.
Падения не скрываются known-failures или успешным повтором; смотреть историю.
При Ctrl+C останавливаются свои процессы и удаляются только собственные
контейнеры/сеть. Отчёты остаются; рабочие файлы и БД игры не удаляются.

Длительность теста сама по себе не доказывает проблему игры: ожидания
таймеров тоже входят во время. Для оптимизации нужны отдельные согласованные
замеры SQL, FPS и нагрузки, которые этот скрипт не запускает.

Документация инструментов: https://bandit.readthedocs.io/en/latest/man/bandit.html
и https://github.com/pypa/pip-audit .


## Актуализация 28.10.2026 после переноса в lava-reborn/server

Полный All обнаруживает все test_*.py автоматически, включая новые файлы:
на момент сверки 207 native-наборов. PostgreSQL запускается отдельным списком
из deploy/ci/pg_suites.sh; это не обещание PG-версии каждого native-теста.
Регрессионный короткий список обновлён до 34 наборов. Учёт изменения исходников
во время прогона теперь включает XML и .filter (специализации и правила поставки).
Модель sparse-массивов в test_weapon_tooltips исправлена: Flash сравнивает их
по идентичности, а не по одинаковому содержимому. Тесты при актуализации не запускались.

Подтверждённые пути для данного компьютера:
- репозиторий D:\Projects\lava-reborn\server;
- Flash dist/actual-tester-client/player/flashplayer_32_sa.exe;
- исходный SWF D:\Projects\lava-reborn\main (1).swf.

В D:\lava-reborn\res статически обнаружены 28 изменённых файлов карты,
включая database/locations.xml. Такой запуск даст полезную диагностику,
но не чистое прохождение эталонов. Для полного gate указать исходный res;
не подменять файлы установленной игры и не ослаблять сравнение.
В выбранном системном Python при сверке отсутствовали psutil/bandit/pip-audit:
перед запуском установить их в .venv-local-checks по инструкции выше.

После завершения прислать report.md/report.json и при ошибках журналы native/ci;
лучше всю папку конкретного запуска logs/local-checks. Не запускать второй
полный прогон параллельно и не менять исходники до завершения первого.
Перед любым разрешённым push проверить origin=https://github.com/lava-reborn/server.git.
Старый репозиторий не использовать. Этот скрипт ничего не коммитит и не публикует.
